# 原型（可丢弃）

这里的文件是回答设计问题的一次性代码，不是产品代码。验证出的决定已回写到 `CONTEXT.md` 与 `docs/adr/`。

## workflow-engine.prototype.html

双击打开即可，无需安装。

**问题**：用「状态类型 + 参与角色 + 每一步的前提条件」描述流程，能否表达通用任务、需求、Bug、发布四种内置任务类型，以及执行记录的开始与结束、Bug 阻塞上线两条规则？

**结论**：能。六个场景（通用任务全程、需求跨角色、Bug 阻塞上线、角色空缺进待领取、发布前置与绕圈检测、越权）全部按预期通过。

**验证过程中改掉的设计**：
1. 状态类型里的"初始"改为"未开始"+ 可领取标记（草稿与待办的区别只在能否领取）。
2. 执行记录不再随进入"进行中"状态自动开始，改为负责人或他的 Agent 自己开始时才开始（ADR 0006）。
3. 参与角色空缺时的交接：任务停在该阶段、负责人为空、进入待领取任务，领取那一刻开始执行记录。

**原型之后定下的**：
- 前置任务被取消或终止时，自动解除它对后续任务的前置关系，留一条动态。
- 一个阶段可以有多段执行记录（提问等待前后各一段），统计按段求和。
- 等待中的任务恢复到"之前那个进行中的状态"，任务需要记住上一个状态（原型用 `$previous` 作为目标）。

`Engine` 那个 `<script>` 块是纯逻辑模块，不碰 DOM，可以直接搬进真实代码。代码内部的英文标识符（Run、Backlog 等）只是代码名，界面上一律用 `CONTEXT.md` 里的中文。
