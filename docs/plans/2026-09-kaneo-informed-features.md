# 功能规划：调研 Kaneo 之后（2026-09-06）

依据 `docs/design/sources/kaneo.md` 与 `kaneo-codex.md` 两份调研，结合 AxiomOS 的定位（目标 → 任务 → 人和 Agent，可定制、可私有化）。每项写清：做什么、为什么、落在哪个模块、边界、依赖。按三批排序，前一批是后一批的基础。

## 第一批：把现有页面用顺（两周量级）

### 1. 任务详情改成「执行简报」
- **做什么**：任务详情按"现在要做什么 → 为什么做 → 前面发生了什么 → 如何验收"四段重排：① 说明与当前状态、可执行的动作；② 目标链（所属目标 → 上级目标）、里程碑、优先级；③ 前置任务的结果、关联、交付物、评论、执行记录；④ 验收人、验收条件、成本。卡片 → 抽屉 → 全页三级密度：列表和看板里点任务先开抽屉（只有①②和最近动态），「打开完整页」进详情。目标详情同理。
- **为什么**：执行者（尤其 Agent）不该跨页面拼上下文；今天的详情按字段排，先看到的是 ID 和创建时间。
- **模块**：任务、目标、`/tasks/{id}/brief` 已有的"任务说明"就是①②的内容，前端直接复用。
- **边界**：不改数据模型；就地编辑照旧。

### 2. 筛选芯片与跨视图保持
- **做什么**：任务页筛选条件显示为可单独移除的芯片（状态、类型、负责人、目标、迭代、优先级、截止日），在列表 / 看板 / 甘特 / 迭代 / 待领取之间切换时保留，写进 URL；「清空」一键。看板和甘特的工具栏与列表同一条。
- **为什么**：用户要看得见"我现在看的是什么"，切视图不该重新设条件。
- **模块**：任务（`TaskFilterBar` 已是共享组件，补芯片与持久化）。

### 3. 动作后果与空状态的全站梳理
- **做什么**：所有不可逆或影响他人的动作（放弃目标、停用成员、合并团队、吊销 Agent、移出迭代、删除目标）在按钮旁或确认框里用一句话写清影响范围与人数；所有空状态写下一步（「这个目标还没有任务，先拆几个出来」+ 动作）。
- **为什么**：IM 集成里已这样做，其余页面不一致。
- **模块**：全站；规范写进 DESIGN.md §6 交互。

### 4. 任务可读序号与个人显示偏好
- **做什么**：组织内递增序号 `#123`，列表、看板、动态、MCP 返回都带；个人偏好：任务列表显示哪些列、看板卡片显示哪些字段（序号、负责人、截止日、优先级、工作量、目标）、默认视图、紧凑模式、侧栏默认状态，一键重置。
- **为什么**：`tsk_xxx` 不可读；不同角色看任务关心的字段不同，与工作台区块同一思路。
- **模块**：任务（序号迁移）、组织设置 → 个人偏好（新页签「我的偏好」，和工作台一样个人 → 角色 → 默认）。

### 5. 前缀式快捷键与命令面板扩展
- **做什么**：`t c` 新建任务、`g c` 新建目标、`v l/b/g/s/k` 切列表 / 看板 / 甘特 / 迭代 / 待领取、`j k` 上下、`Enter` 打开、`n o` 打开待我处理、`?` 快捷键表；命令面板增加"切换范围、跳到目标 / 任务 / 成员、切主题、切语言"。
- **模块**：全站键盘层（已有 ⌘K 与部分快捷键）。

## 第二批：Agent 与外部世界接顺（一个月量级）

### 6. Agent 接入向导与设备码授权
- **做什么**：Agent 页改成向导：① 选运行环境（Claude Code、Cursor、OpenAI Codex、自定义 MCP 客户端）→ ② 系统给一条命令（`npx axiomos-agent connect`）或一段配置，Agent 端执行后打印验证码与网址 → ③ 所有者在网页里确认并选择授权（执行 / 评论 / 需要确认）→ ④ 连接检查（在线、心跳、工具列表）→ ⑤ 试领一个任务。安装器可直接写入各客户端配置文件。设备码绑定的是 Agent 身份，不是用户身份（ADR 0003）。
- **为什么**：现在复制令牌手工贴配置，和 IM 接入一样应该自诊断、逐步引导（`feedback-guided-integration`）。
- **模块**：Agent、MCP、`docs/agent-integration.md`。
- **依赖**：无；复用接入向导的步骤条与检查清单组件。

### 7. 通知外发：三层路由
- **做什么**：账号级通道（飞书私聊、企业微信应用消息、邮件、webhook）配置一次；组织级决定允许哪些通道、哪些事件可外发；个人再按范围与事件类型收窄（只要待确认操作与验收、只要逾期）。站内「待我处理」是事实源，外发只对新事项生效，失败不阻塞并可在通知设置里看到最近投递结果。
- **为什么**：Agent 提交待确认操作时人不在系统里，要能在 IM 里收到并一键打开。
- **模块**：待我处理、通知设置（新页签）、IM 集成（消息通道复用提供方注册表：飞书 / 企业微信各加一个"发消息"能力声明，凭据与检查项共享）。
- **依赖**：IM 集成的提供方模型（已有）。飞书需要「以应用身份发消息」权限，纳入接入检查清单。

### 8. 外部事件触发流程迁移与外部链接
- **做什么**：流程定义里的迁移可以声明"由外部事件触发"（PR 打开 → 进入评审中；PR 合并 → 进入待验收；CI 失败 → 标记阻塞）。任务上可挂外部链接（PR、Issue、设计稿、文档），显示状态（打开 / 草稿 / 已合并）。执行记录记下外部操作者（用户名、来源）。
- **为什么**：研发类任务的真实进度在 Git 平台上，人和 Agent 都不该手动搬状态。
- **模块**：流程定义（ADR 0005 迁移条件扩展）、任务详情、集成（新页签「代码平台」，GitHub / GitLab / Gitee 三个提供方，仍走插件注册表与接入检查）。
- **依赖**：第 6、7 项的提供方与向导组件。

### 9. MCP 与界面同一套解释
- **做什么**：审计全部 MCP 工具的拒绝理由与说明，保证"越权、范围不可见、需要确认、前置未完成、并发已满、任务已结束"六类理由在 MCP 与界面上是同一句中文；工具描述里写清"先取什么再做什么"（先 `get_brief` 再 `begin`）。
- **模块**：MCP、i18n。多数句子已存在，主要是补齐与对齐。

## 第三批：进出与分享（按需）

### 10. 只读分享链接
- **做什么**：目标、迭代、甘特图可生成无需登录的只读链接（可设有效期、可撤销），只显示进度、里程碑、任务标题与状态，不显示成本、成员邮箱。组织策略可整体禁用。
- **模块**：目标、迭代、组织设置 → 可见范围（新增"对外分享"开关）。

### 11. 导入导出与迁移
- **做什么**：任务与目标的 CSV / JSON 导出（当前筛选范围）；导入走与成员导入相同的"预览 → 确认"形态，支持从 Jira、飞书项目、Notion 导出的文件映射字段；迁移进来的对象标来源。
- **模块**：任务、目标、组织设置 → 数据。复用成员导入的匹配与确认区。

### 12. 组织词表统一
- **做什么**：能力标签、任务类型、优先级名称、（若增加）任务标签由组织负责人在一处维护，任务、流程、Agent 引用同一套；改名影响全部引用，删除时说明影响范围。
- **模块**：组织设置（把「能力标签」「流程」「价格表」的词表部分合并成「词表」页签，或保持分页但共用一套改名 / 删除后果提示）。

## 不做
- 工作区 / 项目两层容器、以列为状态、计费座位、社交登录。
