# 主流工具的路线图展示形式调研

调研日期：**2026-09-07**。下面每一条都来自当天实际抓到的官方文档或作者原文；**凡是只有搜索摘要、第三方博客，或原页 404 / 403 打不开的，都写了「未核实」**，请不要当结论用。

## 一、带时间轴的形式

### 逐项对照

| 产品 | 横轴刻度 | 一行是什么 | 分组（泳道） | 没有日期怎么办 | 主要交互 |
| --- | --- | --- | --- | --- | --- |
| **Jira Plans** | 周 / 月 / 季度 / 年 / 自定义区间（快捷键 W M Q Y X） | 任意层级的工作项，可展开子行 | 8 类字段＋部分自定义字段，无值的进底部「未指派」道 | **保留行，右边是空轨**，没有父级的进底部「x 个没有上级的工作项」 | 拖条移动、拖两端改长短；依赖可选「徽标 / 连线」，冲突转红；有自动排期与「假设方案」 |
| **Jira 基础时间线** | 周 / 月 / 季度（缩放还决定新拖出来的条默认多长：7 / 14 / 30 天） | 一个工作项，两层层级 | **没有分组** | 保留行、空轨；父项自己没日期时从子项推 | 拖动、依赖连线、可选进度条 |
| **Jira Product Discovery** | **只有月和季度** | 一条想法 | 有，但控件原名未核实 | **直接不显示** | 拖条；「时间标记」是彩色菱形；无依赖、无排期、无层级 |
| **Linear** | 周 / 月 / 季度 / 年 | **只有项目**——"个别 issue 不上时间线" | 按行动方案或负责人 / 状态 / 健康度等分组（行动方案只作组头，不是第二层条） | 未核实 | 拖条改日期、拖里程碑改日期；项目依赖连线冲突转红 |
| **GitHub Projects** | 月 / 季度 / 年 | 一条工作项，**扁平**（层级视图只在表格布局里） | Group by ／ Slice by ／ Sort | 未核实 | 拖动改起止或所属迭代；「Markers」是横跨全图的**竖线** |
| **Productboard 时间线板** | 周 / 月 / 季度 | 一条记录（目标 / 方案 / 需求 / 版本，可嵌四层） | Add grouping，可再套一层 | **没填时间范围就不显示** | 拖条、拖两端，改的就是数据本身 |
| **Aha! 战略路线图** | 三个月 / 六个月 / 一年 / 自适应 / 自定义 | 一条战略举措，可展开出下级 | 排序或竖拖手动排 | **横跨整幅、两端画成「雾边」** | 横拖改日期、竖拖改次序；按状态 / 负责人 / 类型着色 |
| **Roadmunk（现 Tempo Strategic Roadmaps）** | 周 / 月 / 季度 / 年 | 一条「流」 | 最多两级表头做纵横透视 | 泳道视图里用「桶」值代替日期 | 拖到别的流上避免标签打架 |
| **ProductPlan** | 周 / 月 / 季度 / 月+季度 / 年 / 迭代，还能选「(无)」 | 条 → 容器 → 泳道三层 | 泳道 = 团队 / 产品 / 战略目标 | 选「(无)」整幅不显示日期 | 拖动；里程碑是单日图标，可挂全图或单条泳道 |
| **Notion** | 小时 → 年 | 一条记录，子项可折叠或摊平 | 支持，可再套一层 | **必须有起止才画**；左侧可展开一张表兜住全部条目 | 拖动、拖两端；依赖箭头带三种自动顺延策略 |
| **Airtable** | 天 / 周 / 双周 / 月 / 季度 / 年 / 五年 | 一条记录；分组成泳道，重叠的堆叠 | **最多三级** | **这批里唯一把没排期的留在屏幕上的**：侧栏可筛「没有日期 / 有日期 / 全部」 | 拖动、拖两端、空白处拖出新记录；甘特版有依赖箭头、关键路径 |
| **Asana** | 未核实（帮助中心是 JS 应用，正文抓不到） | 项目时间线一行是任务；组合时间线一行是项目 | 未核实 | 未核实 | 拖动改期、依赖连线；甘特版另有基线与关键路径 |
| **Shortcut** | 一年内 | 目标与史诗并排 | 表格视图按团队 | **必须同时有起止才出现**，否则只在表格里 | 拖条身移动、拖两端改期、上下拖定优先次序 |
| **monday.com** | 天 / 周 / 月 / 季度 / 年 | 一个看板条目 | 按列或按看板分组 | 未核实 | 拖动；用**基线**（灰色影子条）表达偏差 |

### 四条值得单独说的

**Linear 的「日期粒度」是对不确定性最干净的答案。** 开始与目标日期能填成年 / 半年 / 季度 / 月 / 精确到日——"选一个与你把握程度相称的开始与目标日期"。更关键的是粒度怎么消失：**"在时间线上拖动项目的开始与目标日期，会清掉已有的粗粒度（比如月、季度），直接落成精确日期"**（2025-07-10 更新日志）。

**Aha! 是唯一把"完全没日期"画出来而不是藏起来的**："没有日期的战略举措会横跨整幅路线图，条的边缘是雾状的"；对外展示时还能把日期**四舍五入成某月或某季度**——降精度是数据模型里的选项，不是画图时的小聪明。

**Jira 用条的画法区分"这个日期是谁给的"**：从子项推算的父条画成"斜条纹的糖果拐杖花纹"并加箭头，只推出一头的"往那个方向渐隐"；而且"推算只为计划服务，提交回 Jira 时这些推算值不会被保存"，"手工填的日期会覆盖推算值"。

**Atlassian 自己把"路线图"和"排期"划成了两个产品。** JPD 时间线只有月和季度两档，理由写在文档里："它意在呈现一个非常高层的视图，因此不到周的精度"；Plans 那边才有自动排期与容量。这正是我们「路线图 vs 甘特图」的分工——只是他们用**刻度**切，不是用**有没有时间轴**切。

## 二、不带时间轴的形式

| 形式 | 轴是什么 | 卡片带什么 | 故意不做什么 |
| --- | --- | --- | --- |
| **现在 / 下一步 / 以后**（ProdPad 首创，2012） | 三列 = **把握程度**，不是时间 | 一条"待解决的问题"，挂着目标；三档密度可切 | 甘特条、假精度、凭空造的缓冲期 |
| **Aha! 的三列版** | 三列 = 由**某个日期字段**派生（固定周 / 月 / 季度、滚动 60 / 90 天、或自定义区间） | 需求 / 史诗 / 战略举措 | 硬日期 |
| **ProductPlan 列表布局** | 列 = 季度 / 月 / 迭代 / 标签 / 下拉字段 / 目标 | 与时间线上同一批条 | — |
| **Roadmunk 泳道视图** | **纵横都能透视**，列头行头各选一个字段 | 名称、日期或桶值、描述摘要、标签、进度、评论数、子项数 | 适合"没有日期的路线图" |
| **层级视图** | 无轴，靠展开 | Aha! 目标→举措→史诗→需求；Linear 行动方案→项目→issue（子行动方案可嵌五层）；Shortcut 目标→史诗→故事 | — |
| **价值 / 成本 2×2 气泡图** | 两个字段做 X、Y；气泡大小再绑一个字段 | 一条候选想法 | **两轴字段有一个没填，气泡就不出现**；负责人 / 进度 / 里程碑都没有位置 |
| **成果表**（Roman Pichler 的 GO 模板） | 行按时间先后，五列：日期、名称、目标、功能、度量 | 一个成果加它的度量 | 条、依赖；且规定"每个目标的功能列最多三条、绝不超过五条" |
| **山丘图**（Basecamp） | 一座山：上坡"想清楚要做什么"，下坡"把它做完" | 一个点 = 一块范围，不是一个任务 | **没有日期、没有百分比**——"『这个项目完成了百分之几』这个问题本身就不成立" |

**关于三列法，两个必须记住的事实。** 一，ProdPad 现在的定义是"按**把握程度**而不是固定日期来组织"，卡片是问题不是功能，"可以有日期，但只放在真正确定的地方"。二，他们自己列的头号误用就是"把三列当成 Q1、Q2、Q3"，第二号是"Later 变成一个无穷大的垃圾堆"。

**山丘图值得借鉴的不是形态，是两句话**：位置"是人给的，不是机器算的，反映的是一个真人此刻对这件事的感觉"；"一个不动的点等于举手：这儿可能出问题了"。

**最重要的横向结论：没有一家把三列法当成唯一形态。** Productboard 是「时间线板＋分列板」，ProductPlan 是「时间线＋列表」，Roadmunk 是「时间线＋泳道＋表格」，Aha! 一次给八种命名视图。而且两种排布**读写同一批数据**：在分列里把卡片拖到另一列，时间线上那根条的日期跟着变（ProductPlan 原话）。三列法赢的是"一种排布"，不是"一套数据模型"。

## 三、四个难点上，最强的做法长什么样

- **不确定性**：最强是 Linear 的**日期粒度**——不确定性就是日期本身的精度，拖一下就升级成精确；次强是 Aha! 的雾边与对外降精度、Jira 的斜纹与渐隐；最差是"没日期就不显示"（Productboard、JPD、Notion、Shortcut）——读者看不见的东西等于不存在。Airtable 是唯一给"没有日期"一个正式筛选档、把它留在屏幕上的。
- **层级**：都是"父行展开出子行"，没人另起一套视图。取舍最狠的是 Linear：时间线上**只有项目层**。GitHub 到 2026 年层级视图 GA 了也只做在表格布局里。
- **汇总进度**：Asana 从子目标或项目自动算，Productboard 三选一，ProductPlan 每天从执行系统拉一次，Shortcut 按故事数或点数往上滚。共同规则只有一条：**汇总只用于显示，不覆盖人手填的值**（Jira 干脆不落库）。Basecamp 是唯一明确拒绝汇总的。
- **多受众**：有真正对外链接的是 JPD（"让没有 Atlassian 账号的任何人凭链接就能看"，字段可逐个开关）、GitHub 公开项目、monday 公开视图链接、Aha! 分享网页、Productboard 发布板（"其他数据一律不显示"）；没有的是 Jira Plans 与 Linear。共同点：不给搜索引擎收录、可加密码、字段减配。
- **路线图与排期的过渡**：靠**刻度**和**层级**切开，不靠两个互不相干的页面——Linear 四档分辨率、Aha! 三个月 / 六个月 / 一年、GitHub 月 / 季度 / 年，都是同一张图缩放。

## 对 AxiomOS 的结论

### 哪几种形式真的合适

我们的单位是**目标**：有负责人（必须是人）、有团队、有里程碑、有汇总出来的进度、还有预算。这跟三列法的单位（"还没定型的问题"）不是一个东西，跟 2×2 的单位（还没决定做不做的候选）更不是。对得上的只有两种：

1. **粗刻度的目标时间线**——行是目标、横轴是日历季度、里程碑是条上的菱形。这是 Linear、Aha! 战略路线图、Productboard 时间线板共同的形态，也是唯一能同时放下负责人、进度、里程碑的形态。
2. **成果表**（GO 模板那种：时间、名称、成果指标、进度、负责人）——扁平、能直接读、适合对外发和往文档里贴。

三列法降为**同一批数据的第二种排布**，不再是唯一形态；并且列要**由日期派生**（Aha! 的做法），不再靠一个和日期各说各话的独立枚举。

### 推荐布局（按这个实现）

**页签结构不变**：目标页仍是路线图、树、甘特图三个页签，默认仍是路线图。变的是路线图页签内部多一个排布切换：**时间线（默认）／ 分列**，两种排布同一批目标、同一个范围、同一套筛选。

**时间线排布**

- **横轴**：日历，只开三档刻度——月 / **季度（默认）** / 年。复用 `gantt/scales.ts` 已有的 `month | quarter | year`，**故意不开周 / 天 / 时**：那三档是甘特图的事，开了路线图立刻退化成排期表。今天线保留。这一条不是省事，是 JPD 的原话："它意在呈现一个非常高层的视图，因此不到周的精度。"
- **一行 = 一个目标**。子目标缩进嵌套、可折叠；折叠后父行画跨整棵子树的汇总条——`GoalGanttView` 已经是这个行为，直接复用。
- **泳道**：默认按团队分组，可切「按负责人」或「不分组」。ADR 0021 里泳道那一条原样保留。
- **左侧固定信息列**（约 320px，不随横轴滚动，四行）：① 目标标题，前面一枚**信心度圆点**（高＝成功色、中＝中性、低＝警示色，没填不画）；② 成果指标，单行截断、淡一级；③ 负责人头像＋名字；④ 细进度条＋百分比。"一眼读出进度与信心度"靠这一列，不靠条。
- **条的四种画法**，把"这个日期有多硬"直接画出来：
  1. **粒度到日**——硬边实条，和甘特图一样。
  2. **粒度是月 / 季度 / 半年 / 年**——两端吸附到刻度边界，边缘做一格宽的渐隐（学 Aha! 的雾边）。
  3. **自己没填、从子目标推出来的**——条身画斜纹并在标题旁加一枚箭头，只推出一头的那一头渐隐（学 Jira）。**推算值不落库**，父目标一旦自己填了就用它自己的。
  4. **完全没有日期**——见下。
  条内按汇总进度填充，沿用 `GOAL_FILL` 的三种语气（进行中 / 已达成 / 已放弃）。**路线图上永远不出现"某月某日"**。
- **里程碑**：条上的菱形（复用 `gantt/MilestoneMarks`），逾期实心标红，已达到打勾。这是路线图上唯一露出具体日期的地方，与 ADR 0021 卡片形态的用意一致。
- **没有日期的目标不藏**。沉到本泳道底部的「还没排期」小分组，左侧信息列照常显示，右侧从今天线起画一根极淡的虚线幽灵条，上面一句「按住往右拖就算排期了」——拖出来写进计划起止，拖两端改长短，不给日期选择器。工具条上一个「只看已排期」开关给不想看它们的人。这一条有两个先例：Jira 保留空轨行，Airtable 给了「没有日期」一个正式筛选档。
- **拖动就是表态**：在时间线上拖条或拖两端，把时间粒度**清成"到日"**（Linear 的规则）。想回到粗粒度，去目标详情改粒度。
- **往下钻**：行首箭头展开子目标；点标题进目标详情（详情里已内嵌该子树的任务视图）；行尾一个按钮跳到任务甘特图并预置该目标的筛选。**路线图本身不画任何任务**——这是 Linear 的取舍，也是我们和甘特图页签的分界。

**分列排布**

三列现在 / 下一步 / 以后加「还没排期」，卡片形态就是现在这套，值得保留。唯一改动：**一个目标落在哪一列，先看计划起止**——落在当前季度是"现在"，接下来两个季度是"下一步"，更远是"以后"；两头都没日期时才读它自己填的时间桶。拖卡片换列时：本来有日期的，改的是日期（吸到该列对应的区间）；没日期的，改的是时间桶。这样两种排布不会互相打架。

### ADR 0021 保留什么、改什么

**保留**：`horizon`、`confidence`、`outcome` 三个字段和迁移，一个不删；三档写死、不做成可配置词表；泳道口径（团队 / 负责人）属于看法不属于策略；对外只读分享仅限路线图与目标甘特图、不含成本。

**改**：
1. 「路线图页签永远不画时间条」这一条**推翻**。它是这轮不满意的根源：去掉时间轴之后，目标身上已有的计划起止、里程碑日期全部失去位置，读者只剩三堆卡片。改成"路线图不画**日**，只画月 / 季度 / 年"——把"不承诺精确日期"交给刻度和日期粒度去保证，而不是交给"什么都不画"。全行业没有一家用"取消时间轴"来解决这个问题，他们用的是**降刻度**。
2. `horizon` 从"没有日期时唯一的时间表达"降为**兜底**：有日期时分列由日期派生，没日期时才读它。ADR 0021 说的"互不覆盖"保留，但明确了谁优先。
3. 默认排布是时间线，不是分列。默认页签仍是路线图。
4. 对外分享按日期粒度**降精度**（学 Aha!）：粒度是季度就只发"2026 年第四季度"，不发具体区间。
5. 汇总**只在读时算、不落库**（学 Jira）：父目标自己填了计划起止就用自己的，没填才从子目标与任务推，推出来的值不写回、并且在条上画成斜纹，让人一眼看出这是算的不是定的。

### 两个被否决的方案

**否决一：继续用三列＋泳道作为唯一形态。** 三列法的单位是还没定型的问题，靠"细节随把握程度递减"省信息；我们的目标恰恰相反——一立项就有负责人、团队、里程碑、进度、预算，塞不进三列。ProdPad 点名的头号误用就是"把三列当季度"，而我们的目标本来就大量带精确日期，这个退化是必然而非风险。更要命的是：把时间桶做成与日期无关的独立枚举，等于让同一个目标有两套互相矛盾的时间表达——没有一家主流工具这么干，Aha! 的三列是从日期字段**派生**的。

**否决二：价值 / 成本 2×2 气泡图当路线图主视图。** 它是**取舍**的视图，输入是还没决定做不做的候选（JPD 官方举例就是"影响 vs 成本，以及把握程度"），而且缺数据时"两轴有一个没填，气泡就不出现"——对必须全部被看见的目标是致命的。2×2 上也没有负责人、进度、里程碑的位置。它以后可以做成新建目标时的排序辅助，不该是路线图。

（山丘图也不做：点是人手拖的，"是人给的，不是机器算的"，而我们有真实的汇总进度和执行记录，用手拖的点盖住真数据是倒退。但**历史快照**值得单独立项——动态是只增不改的，按周回放一个目标的条与里程碑成本很低，"一个不动的点等于举手"这个信号我们现在完全没有。）

### 需要给目标加的字段

1. **时间粒度**（code: `DatePrecision`，取值 `day | month | quarter | half | year`，可空）——**必须加**。吸附、雾边、对外降精度、"分列由日期派生"全靠它。语义是"这个日期填到什么精细度为止"，不是"我有多大把握"（把握是信心度，两者正交：可以季度粒度＋高信心度，也可以到日＋低信心度）。默认空等价于 `day`，旧目标不受影响；在时间线上拖条时自动清成 `day`。这是 Linear 项目时间粒度的直接对应物。
2. **排序权重**（code: `Rank`，可空）——泳道内的手动次序。Aha! 竖拖排序、Shortcut 上下拖定优先次序、Jira Plans 把排名当第一列；我们现在只能按日期或创建时间排，一条泳道里有七八个目标就没法表达"这个更要紧"。

其余不用新加：负责人、团队、进度、里程碑、成果指标、信心度、时间桶都已在库里，`gantt` 那套刻度、缩放、今天线、菱形渲染器也都写好了。
