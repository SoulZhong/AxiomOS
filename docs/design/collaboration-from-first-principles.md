# 人与 Agent 的协作：从第一性原理重做

日期：2026-09-09 · 状态：已拍板，ADR 0028 起草中（Codex 评审一轮后收窄范围，见 ADR 末尾）
来源：一天的真实使用（`sources/collab-retro-brief-2026-09-08.md`）、Codex 的独立评审（`sources/collab-retro-codex-2026-09-08.md`）、所有者的三条反馈。

## 一、问题的真正形状

所有者的三条反馈：

1. 要在 AxiomOS 里确认的操作太多，每条给的信息又不够做判断。
2. 既要在 AxiomOS 里操作，又要在 Agent 里操作，很割裂；只想在 Agent 里工作，工作过程中不碰 AxiomOS。
3. 在 AxiomOS 里看不到目标和任务的进展、token 与成本。

Codex 从流水里补的：Agent 在没有执行记录、没拿到执行授权时先把活干完，再用一串待确认操作把既成事实补录进流程；「经确认」不知道确认的是哪个版本；本地文件路径被当成 PR 进了验收；心跳超时没有恢复协议；重连换了 Agent 就断了责任链；用量为 0 是事实失真而不是观测缺失。

这些不是七个 bug，是一个模型错位：**AxiomOS 把「授权」建在操作类型上，把「控制台」建在网页上，把「问责」建在预先审批上。** 于是人把一件事交给 Agent 之后，还得为这件事的每一个动作到网页上点头；点头时看到的只是一句话；而真正该问责的东西（谁、凭什么、花了多少、证据是什么）反而没有记全。

## 二、原则

从头想，一个组织里人和 Agent 协作，不可再分的事实只有这几条：

1. **委托的是结果，不是操作。** 人说的是「这个任务你做」，不是「你可以附交付物」。授权的自然单位是一件事的范围加一个预算，不是动作类型。
2. **该问人的只有三类事。** 不可逆的对外副作用（花钱超预算、对外发消息、合并代码、删除）；责任变更（谁负责、做什么范围、方案外新增）；验收（结果算不算数）。其余动作只需要**可观测、可追溯、可撤回**，不需要预先点头。
3. **权威来自人，Agent 是工具。** 授权判定看所有者是谁，问责记录看是哪个 Agent 在哪次执行里做的。两者分开记，任何一条动态都能回答「谁的授权、哪个工具、哪次执行、改了哪个版本」。
4. **人在哪里，决定就送到哪里。** 人在 Agent 客户端里工作，决定就在客户端里问；人在飞书里，就发到飞书；网页只是其中一个入口，不是唯一入口。
5. **系统能自己观测到的，不靠 Agent 自报。** 执行时长、写了什么、调了几次工具、心跳有没有断，服务端自己记；token 由客户端侧的钩子送来；拿不到就说「未上报」，永远不写 0。
6. **交付物要能验证来源。** 一个「PR」必须真的是代码平台上的 PR；一个文件必须指向某个提交；不能验证的只能叫链接。

## 三、对象模型

现有对象里，任务、目标、流程、执行记录、动态都保留。变的是三件事：用**委托**取代「按操作类型的授权 + 待确认操作」；用**决定**取代「待确认操作」作为问人的单位；执行记录成为问责的容器而不是一个要审批的动作。

### 委托（code: `Mandate`）

所有者把一个范围交给一个 Agent 的凭据。一份委托包含：

| 字段 | 含义 |
|---|---|
| 范围 | 一个任务；方案批准时给方案里每个任务各发一份，共用一个方案编号 |
| 预算 | 成本上限、token 上限、截止时间，任一超出即停下来问 |
| 副作用许可 | 对外动作逐项写明：推代码到平台、发消息到 IM、改外部链接；默认全关 |
| 要问我的事 | 组织默认 + 所有者微调：责任变更、取消、方案外新增、超预算、验收 |
| 有效期与版本 | 绑定任务版本与负责人；任务换人、改目标、改范围即失效 |

有效权限 = 所有者权限 ∩ Agent 的能力授权 ∩ 委托范围 ∩ 流程当前步骤。ADR 0003 的交集不变，只是多了两项，而且那两项才是人真正在意的。

委托怎么产生：批准目标方案时（一次批准 = 方案里每个任务一份委托）；指派任务给 Agent 时；Agent 领取待领取任务时（组织可配「领取即委托」或「领取后问一次」）。授权预设（开发 / 产品 / 测试 / 只读）改成**委托模板**：预设的不是十项操作的三选一，而是「预算多少、哪些副作用、哪些事要问我」。

委托之内的动作直接生效：开始执行、心跳、写进展、附交付物、按流程推进（`by: assignee` 的步骤）、在本任务下建子任务与关联、提问等待。每一条都记账（见「执行记录」），并且在一段时间内可由所有者撤回（状态回退到上一步、交付物撤下），这是「不预先问」的对价。

### 决定（code: `Decision`）

问人的单位。不再是「附交付物 A」这样的操作，而是一个人能一口气回答的问题：

- 「把这份方案交给你的 Claude Code 做到底吗？」预算、副作用、要问的事一次列出。
- 「#12 做完了，验收通过吗？」附交付物、执行记录、成本、与上一版的差异。
- 「#14 改派给 X？」附原因、当前进度、影响到的下游。
- 「预算用到 90%，继续吗？」附花在哪了。
- 「方案外要新增一个任务，可以吗？」附它与目标的关系。

一个决定携带：要改什么（改前改后对比）、证据（交付物可点开、执行记录可展开）、到目前的成本、风险等级、可选答案（同意 / 拒绝 / 改一下再同意，如换负责人、去掉几项）。同一任务同一阶段里 Agent 连续提出的几件事合成**一份**决定，高风险项单独列，逐项可剔除。

决定绑定对象版本。对象在等待期间变了，决定自动作废并通知 Agent 重提。这解决 Codex 的「经确认不知道确认的是哪个版本」。

### 执行记录（code: `Run`）

从「要审批的动作」变成「问责的容器」。Agent 在委托范围内的第一个写动作自动开一段执行记录，不再有单独的「开始执行」要人确认；心跳断了进入「中断待续」而不是「失败」，同一 Agent 在租约内续接，续不上才由人决定重开或改派。执行记录上分两层记账：

- **服务端观测**：起止时间、状态停留、写了哪些对象、调了几次工具、心跳间隔。无条件记。
- **客户端上报**：按模型的 token 数与折算成本。由接入脚本装进客户端的钩子自动送（Claude Code 的会话记录里有每条消息的用量，钩子读它、按任务累计、打到心跳接口）；Agent 本身不必再「记得」报用量。

没有上报的显示「未上报」，成本汇总里标明「n 段执行记录未上报」。

### 身份

授权看所有者，问责看 Agent。由此：

- 流程里 `by: creator` 等角色规则对 Agent 的判定改为「创建者本人，或创建者所属所有者的任一 Agent」，动态里同时记所有者与实际的 Agent。责任链不断，权限范围没有扩大（还是那个人的）。
- 重连时按「所有者 + 客户端 + 机器」识别出上一个 Agent，接入向导默认「续接上一个」，续接生成一条转移动态；新建是显式的第二个选项。
- 一个所有者名下的 Agent 的并发配额与预算怎么共享，与身份续接一起在 ADR 0031 里定；委托模型本身不碰它。

### 交付物

带来源：代码平台对象（PR、提交，由平台事件验证）、仓库里的文件（指向某个提交）、系统生成的报告（测试、发布记录，由系统写入）、外部链接（不验证）。流程要求可以写 `artifact:pr(verified)`；验收界面标明每件交付物「已验证 / 未验证」。本地未提交路径只能作为「未验证文件引用」，满足不了 PR 类要求。

## 四、人的工作面：Agent 客户端

所有者在工作过程中不打开 AxiomOS。要做到这一点，四件事必须在客户端里完成：

1. **决定在客户端里答。** 首选 MCP elicitation：服务器直接向客户端弹一个表单，人点一下，答案不经过模型。go-sdk 已支持，需要验证当前 Claude Code 版本能否接住；`/confirm` 保留为兜底（客户端不支持时）。飞书 / 企业微信卡片是并行通道，同一份决定、谁先答算谁的。
2. **验收在客户端里做。** 决定的一种；卡片里能看交付物与差异。
3. **状态在客户端里看。** 两条斜杠命令：`/status`（我的目标：进度、里程碑、成本对预算、等我的决定数）、`/decide`（列出等我的决定并逐份答）。
4. **改字段在客户端里改。** 参与角色、并发、预算这些今天只能在网页改的，Agent 可以提议，人答一个决定。

Agent 那一侧的协议同时变简单：不用记得 `begin_task`，不用记得报用量，写动作自动归到执行记录；被阻塞时调 `wait_for`（等某个决定、等某个前置、等重连），任务上出现结构化的「等人」状态与原因，简报和 `next_actions` 都能看到。

## 五、网页：看板，不是控制台

网页保留三种用途：**看**（目标与组织的进展、成本、Agent 表现）、**配**（组织设置、流程、委托模板、外部目录与平台）、**兜底**（没有 Agent 客户端的人处理决定）。

目标页顶部一块固定汇总：任务按状态的进度条、里程碑到期、成本对预算、按 Agent 与按人的拆分、未上报的执行记录数。首页「我的工作」给每个目标同样的一行摘要。「待我处理」里的每一份决定与客户端里看到的是同一份内容。

## 六、要人出手几次：下限是什么

把「问人」的三类事再往下拆，每一类都能问自己：这件事非要人在**这个时刻**点头吗，还是人事后看一眼、不满意能撤回就够了？

- **责任变更**：方案批准那一刻已经把责任定了。方案里写清负责人、预算、副作用、验收标准，之后责任不变就不必再问。
- **验收**：验收的本质是「结果算不算数」。写得出客观标准的（测试通过、PR 已合并、交付物已验证、前置任务的结果被引用），系统自己判，叫**自动验收**；写不出的，在**里程碑**这一层由人一次看全，不逐个任务看。任务级的人工验收只留给方案里明确标了「要我亲自看」的任务。
- **不可逆的对外副作用**：委托里逐项许可过的不问；没许可的才问。多数内部目标一项都没有。

剩下的是**例外**：预算超了、对外动作没许可、Agent 卡住要人给信息。这些不是确认，是真的需要人的输入，躲不掉，也不该躲。

于是一个目标的下限是**两次**：一次把目标交出去，一次在里程碑上认结果。中间人收到的是摘要，不是问题：每天（或每个里程碑）一份「做了什么、花了多少、卡在哪」，人不满意就撤回某一步或收回委托，满意就不用动。这是例外管理：默认前进，人只处理例外。

以本次目标（9 个任务，全部交给一个 Agent）为例：

| 环节 | 现在 | 改后 |
|---|---|---|
| 分解目标 | 1 次批准方案 | 1 份决定：批准方案 = 委托 + 预算 + 副作用 + 每个任务的验收标准 + 摘要节奏 |
| 每个任务开始、附交付物、推进 | 每任务 4–6 条待确认操作 | 0，自动记账，可撤回 |
| 角色槽位空、换人 | 每次 1 条 | 0（委托覆盖整个任务；创建者规则按所有者判） |
| 重连 | 取消重建、重新指派 | 0，续接留一条转移动态 |
| 任务验收 | 网页逐个，9 次 | 0：达到方案里写的客观标准即自动验收；证据挂在任务上 |
| 里程碑 / 目标验收 | 无 | 1 份决定：两个里程碑合成一份，附全部证据与成本，可逐项打回 |
| 中途 | 反复「等你操作」 | 摘要若干份，不需要回答；例外才问 |
| 合计要人出手 | 约 30 次，两边切换 | 2 次，全在客户端 |

第一次那份决定要承担得起「之后不再问」，所以它必须完整：方案预览里每个任务标明负责人、预算、验收标准、首步是否可执行（Codex 提的可达性预检），人能逐项改再批。批得草率是人的选择，系统给足信息就行。

验收标准写不出来的任务怎么办：方案里标「要我亲自看」，它就是任务级人工验收，进那份里程碑决定里作为单独一项。这是人主动加的例外，不是系统默认。

## 七、与现有决定的关系

| ADR | 处理 |
|---|---|
| 0003 权限交集 | 保留公式，补两项：委托范围、当前步骤；「需要人确认」这一档退役，由委托的「要问我的事」取代 |
| 0006 执行记录只由本人开启 | 保留精神，实现改为「委托内的第一个写动作即开启」；仍不会在状态进入时自动开 |
| 0014 什么可配 | 委托模板与「要问我的事」是组织可配的；六类拒绝理由、决定的结构写死 |
| 0018 设备码 | 加「续接上一个 Agent」为默认路径 |
| 0020 外部事件 | 不变；交付物验证依赖它 |
| 0025 确定性 | 不变；`dry_run`、幂等键、`ResolveRef` 继续适用于所有写工具 |
| 0026 目标方案 | 批准即发委托；方案里每个任务带验收标准与预算；预览加可达性预检（角色、能力、首步可执行） |
| 0027 客户端里确认 | `/confirm` 降为兜底；首选 elicitation；决定取代待确认操作 |

词汇表新增：委托、决定、自动验收、摘要、中断待续、未上报、已验证 / 未验证交付物。「待确认操作」保留为历史词，界面不再出现。

## 八、分期

1. **委托与决定（ADR 0028）**：数据模型、权限公式、决定的合并与版本绑定、撤回；方案批准即委托，方案带验收标准；自动验收与里程碑验收；摘要。这一步就把出手次数从三十次降到两次。
2. **决定在客户端里答（ADR 0029）**：验证 elicitation；`/status`、`/decide`、`wait_for`；验收进客户端；IM 卡片并行。这一步让人不再打开网页。
3. **执行记录的观测与用量（ADR 0030）**：自动开启、中断待续、两层记账、客户端钩子上报、目标页汇总。这一步让进展与成本可见。
4. **身份与交付物真实性（ADR 0031）**：按所有者判角色规则、续接、共享配额；交付物来源与验证。

每一期都独立可用，顺序按痛点排。

## 九、风险与不做的事

- **撤回不是万能的**：对外副作用不可撤，所以委托对副作用默认全关，开一项问一次。
- **委托范围泄漏**：任务换人、改目标即失效，靠版本绑定保证；不做「按 Agent 全局放行」。
- **elicitation 客户端支持不齐**：兜底路径必须一直在；不因某个客户端不支持就退回网页。
- **钩子上报可被伪造**：token 本来就只能信客户端；服务端观测的那一层是独立的，成本口径标明来源。
- **不做的**：不给 Agent 任何替人做决定的工具；不把决定降级成聊天里的一句「确认」；不为减少确认而让 Agent 跳过流程阶段。
