# ADR 0016：里程碑是目标的时间刻度，不是任务

日期：2026-09-05 · 状态：已采纳 · 关联：ADR 0004、0005、0014

## 背景

目标只有计划起止与截止日，看不出"中间应该到哪一步"。用户要求目标也能以甘特图呈现，并能设立里程碑。

## 决策

1. **里程碑属于目标**（`milestones.goal_id`），有名称、日期、可选说明、`reached_at`。它没有执行者、没有流程、没有执行记录与成本，因此**不是任务**，也不做成任务类型；把它做成任务会让"到某一天应达到什么"混进"谁去做什么"。
2. 「已达到」由目标负责人（或能编辑该目标的人）确认，不自动判定；系统只提示：日期已过且未确认为逾期，日期前所有计划结束早于该日的任务已完成时提示"可以确认了"。
3. **目标甘特图**是目标页的一个页签，不是新入口（DESIGN.md §10）：每个目标一条横条（计划起止，进度填充，截止刻度），子目标嵌套可折叠，里程碑是横条上的菱形，今天线与刻度沿用任务甘特图。任务甘特图按目标分组时，目标汇总行同样画出菱形。
4. Agent 对里程碑的增改删受「创建目标」授权约束（里程碑是目标的一部分），模式为需确认时走待确认操作。每次写操作产生动态。

## 代价

- 多一张表与一组接口；目标树与甘特图接口要带里程碑摘要。
- 里程碑与任务的截止日容易被混用，界面上里程碑只出现在目标的行上、用菱形，任务永远是横条。

## 被否决的方案

- **里程碑做成零工时的任务**：会出现在看板、待领取、负荷里，污染所有任务视图。
- **用子目标充当里程碑**：子目标有进度与任务，里程碑只是一天；混用后目标树会被一堆"日期目标"撑爆。
