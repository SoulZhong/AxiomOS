# ADR 0015：首页是按角色配置的工作台

日期：2026-09-05 · 状态：已采纳 · 关联：ADR 0013、0014

## 背景

不同的人打开系统的第一屏应该是自己的活：CEO 要看全公司概览与异常，部门负责人要看本部负荷与待确认，员工要看我的任务。此前首页只有一条写死的规则，其余人一律"我的任务"。按 ADR 0014，"谁先看什么"是管理策略，必须由组织自己配。

## 决策

1. **首页是工作台**，由若干**区块**按顺序组成。区块是系统定义的有限集合（组织概览摘要、要我关注的异常、我的任务、等我验收、人员与 Agent 负荷、成本与预算、待确认操作、最近动态、当前迭代、待领取任务、趋势与环比），每个区块只读同一份数据，服从当前范围。
2. **布局按角色配置**：组织管理员给每个角色配一套区块与顺序；成员有多个角色时取并集，按首次出现的顺序合并去重。成员可以在自己的首页上**微调**（隐藏、排序），个人调整只影响自己，可一键恢复角色默认。
3. **系统只发预设**，不写死角色名。预设按"这类人关心什么"命名：全局视角、部门视角、小组视角、执行视角、运营视角。组织把预设套到自己的角色上，也可以逐块改。没有任何配置时，组织负责人用全局视角，其他人用执行视角。
4. 同一个区块靠**范围**服务不同层级：组织概览对 CEO 是全公司、对部门负责人是本部，是同一个区块、同一套口径。不为不同层级做不同页面。

## 代价

- 首页要区块化重构；新增一张布局表与一组接口。
- 区块集合是系统定义的，客户不能自造区块（要自造就是新需求）。

## 被否决的方案

- **按人群做多套首页或多套应用**：口径分叉，维护成本随人群数线性增长。
- **用权限表达"先看什么"**：会逼着客户为了改首页去改权限，混淆"能做"与"先看"。
- **完全自由的拖拽仪表盘**：灵活但每个人都要自己搭，绝大多数人不会搭；预设加微调覆盖了绝大多数诉求。

## 补记（2026-09-05，DESIGN.md §12）

- 「首页」改名「我的工作」，顶部新增**固定的「待我处理」**：汇总等我确认的待确认操作、等我验收的任务、我负责但逾期的任务、指派给我但没开始的任务、等我答复的提问、未读通知，只看本人、不受范围影响，不能被隐藏或挪走。工作台区块在它下面，本 ADR 的预设与解析规则不变。
- 区块目录移除 `proposals`（已被待我处理覆盖）；已存布局里出现它时忽略。
- 「待确认操作」不再是导航入口，其历史记录保留为 `/proposals/` 子页。
