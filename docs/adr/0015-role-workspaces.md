# ADR 0015：首页是按角色配置的工作台

日期：2026-09-05 · 状态：已采纳 · 关联：ADR 0013、0014

## 背景

不同的人打开系统的第一屏应该是自己的活：CEO 要看全公司概览与异常，部门负责人要看本部负荷与待确认，员工要看我的任务。此前首页只有一条写死的规则，其余人一律"我的任务"。按 ADR 0014，"谁先看什么"是管理策略，必须由组织自己配。

## 决策

1. **首页是工作台**，由若干**区块**按顺序组成。区块是系统定义的有限集合（组织概览摘要、要我关注的异常、我的任务、等我验收、人员与 Agent 负荷、成本与预算、待确认操作、最近动态、当前迭代、待领取任务、趋势与环比），每个区块只读同一份数据，服从当前范围。
2. **布局按角色配置**：组织管理员给每个角色配一套区块与顺序；成员有多个角色时取并集，按首次出现的顺序合并去重。成员可以在自己的首页上**微调**（隐藏、排序），个人调整只影响自己，可一键恢复角色默认。
3. **系统只发预设**，不写死角色名。预设按"这类人关心什么"命名：全局视角、部门视角、小组视角、执行视角、运营视角。组织把预设套到自己的角色上，也可以逐块改。没有任何配置时，组织负责人用全局视角，其他人用执行视角。
4. 同一个区块靠**范围**服务不同层级：组织概览对 CEO 是全公司、对部门负责人是本部，是同一个区块、同一套口径。不为不同层级做不同页面。

## 代价

- 首页要区块化重构；新增一张布局表与一组接口。
- 区块集合是系统定义的，客户不能自造区块（要自造就是新需求）。

## 被否决的方案

- **按人群做多套首页或多套应用**：口径分叉，维护成本随人群数线性增长。
- **用权限表达"先看什么"**：会逼着客户为了改首页去改权限，混淆"能做"与"先看"。
- **完全自由的拖拽仪表盘**：灵活但每个人都要自己搭，绝大多数人不会搭；预设加微调覆盖了绝大多数诉求。

## 补记（2026-09-05，DESIGN.md §12）

- 「首页」改名「我的工作」，顶部新增**固定的「待我处理」**：汇总等我确认的待确认操作、等我验收的任务、我负责但逾期的任务、指派给我但没开始的任务、等我答复的提问、未读通知，只看本人、不受范围影响，不能被隐藏或挪走。工作台区块在它下面，本 ADR 的预设与解析规则不变。
- 区块目录移除 `proposals`（已被待我处理覆盖）；已存布局里出现它时忽略。
- 「待确认操作」不再是导航入口，其历史记录保留为 `/proposals/` 子页。

## 补记二（2026-09-06）：整页可定制

用户要求每个区块可调大小、可增删、整页可定制。本 ADR 原先否决的是"完全自由的拖拽仪表盘"，理由是绝大多数人不会搭；现在的折中是**受约束的自由布局**：

- 版面是 12 栏网格；每个区块有宽度（3 / 4 / 6 / 8 / 12 栏）与高度（紧凑 / 标准 / 高 三档），按顺序自动流式排布并致密填充，不做像素级自由摆放。
- 区块仍是系统定义的有限集合；「添加区块」只能从目录里选还没放上的。「待我处理」固定在顶部、全宽、不可删除。
- 布局对象从 `blocks[string]` 变为 `blocks[{key, w, h}]`；旧形状继续接受，缺省宽高取区块目录里的默认值。预设带默认宽高。
- 角色布局与个人布局都用同一个编辑器；解析与合并规则不变（个人 → 角色并集 → 默认），合并时宽高取首次出现的那份。

## 补记三（2026-09-06）：直接拖动，不用分段按钮

用户否决了"分段选择宽高"的编辑方式，要求拖动位置与拖动边框改大小。因此：

- 布局块携带坐标：`{key, x, y, w, h}`，12 栏网格，行高单位约 120px；`w` 为 `min_w`…12 的任意整数，`h` 为 1…6 的任意整数，不再限定档位。
- 编辑模式下：按住区块任意位置拖动即移动，拖右边、下边或右下角改大小，都按网格吸附，其他区块自动让位并向上压实（不留空洞）。没有工具条，只有右上角的移除。
- 旧形状（只有顺序与宽高、或只有键名）继续接受：缺 `x/y` 时由前端按顺序致密排布后回写。
- 实现上前端采用成熟的网格布局库（react-grid-layout，MIT）承担拖动、吸附、碰撞与压实，样式用本系统的 token 覆盖。

## 补记四（2026-09-06）：「待我处理」与「组织概况」也是区块

用户要求这两块同样能拖动、改大小、移除。撤销补记里"待我处理固定在顶部、不可删除"的规定：

- 新增区块 `inbox`（待我处理，默认 12×2，最窄 6 栏；只看本人、不受范围影响，这一点不变）和 `readouts`（组织概况：进行中 / 待验收 / 逾期 / 今日成本四个实时读数带 24 小时趋势线，默认 12×1，最窄 6 栏）。页面上不再有布局之外的固定区域，整页都是网格。
- 所有预设把 `inbox` 放在最上面、`readouts` 紧随其后（面向执行者的预设不带 `readouts`）。
- 迁移：已存的个人与角色布局在最上方补上 `inbox` 与 `readouts`（其余区块下移），之后是否保留由使用者决定；移除后可从「添加区块」找回。
