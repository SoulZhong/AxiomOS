# ADR 0030：用量自动采集——token 由客户端记账，归口到执行记录，没归口的记在 Agent 名下

日期：2026-09-10 · 状态：已采纳 · 关联：ADR 0006（执行记录）、ADR 0025（幂等）、ADR 0028（委托）

## 背景

所有者反复问「为什么看不到任务消耗的 token」。查下来任务与 Agent 名下的用量全是 0，原因有两层：

1. 用量只能靠 Agent 在心跳里**自报**（`heartbeat` 的 `usage`）。Claude Code 不把 token 计数暴露给模型，Agent 报不出准数，实际一次都没报。
2. 很多活是人在客户端里直接吩咐做的，没有挂在任务上、没开执行记录，本来就没有归口的地方。

价格表、任务成本、目标预算这一整套都在等这个数。

## 决策

### 1. 数字由客户端自己记的账来，不靠模型自报

Claude Code 把每一轮的用量写进本地会话记录（每条助手消息带 `usage`：输入、输出、缓存读、缓存写与模型名）。接入脚本（`/connect`）给 Claude Code 装一个 **Stop 钩子**（`~/.axiomos/usage-hook.py`，写进 `~/.claude/settings.json` 的 `hooks.Stop`）：每轮结束读会话记录，按消息 id 去重、按模型累计，把**整个会话的累计数**报到 `POST /api/v1/me/usage`。令牌与地址从 Claude Code 自己的 MCP 配置（`~/.claude.json` 的 `axiomos`）读，不另存一份。钩子任何情况下静默退出，不拖住客户端。Cursor / Codex 各自的接入脚本照同一接口做（本期只做 Claude Code）。

### 2. 服务端算增量，累计数幂等

`agent_usage_sessions` 按 (Agent, 会话, 模型) 存上一次看到的累计数；每次上报与它比较得出增量，累计数只增不减（客户端重启、记录被截时不倒扣），同一份数报多少次都只算一次（ADR 0025 那套幂等思路）。

### 3. 归口：那一刻有开着的执行记录就归到它，没有就是「未归口用量」

- 上报的那一刻这个 Agent 有开着的执行记录（几段同时开着取最近有心跳的那段）→ 增量加到那段的累计用量上，走原来的心跳（内核取最大、价格表折算成本、动态 `UsageReported`）。任务页、目标预算、组织概览的成本立刻有数。
- 没有开着的执行记录 → 记成**未归口用量**（`agent_usage_entries` 里 `run_id` 为空），在 Agent 名下按时间累着，`get_my_metrics` 与 Agent 页显示；动态记一笔 `AgentUsageRecorded`。**不追溯**：过去的未归口不会因为后来开了执行记录而搬过去——不知道那些 token 是干什么花的，宁可写「未归口」。

### 4. 不做的事

- 不让模型估 token。
- 不按工具调用次数或时长猜成本。
- 不把未归口用量摊到任务上。

## 后果

- 人在客户端里直接吩咐的活，token 会以「未归口」的形式出现——这恰恰是「这些活没挂在任务上」的证据，是推动「先领任务再干」的钉子。
- 一份会话的用量只归到一段执行记录：同一会话里并行做几个任务时，全归到最近有心跳的那段。做精细分摊要等客户端能按工具调用标记任务。
- 接口：`POST /me/usage`（Agent 令牌）、`GET /agent-auth/usage-hook.py`（公开，接入脚本下载）。表：`agent_usage_sessions`、`agent_usage_entries`（迁移 0027）。
