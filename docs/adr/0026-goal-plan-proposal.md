# ADR 0026：Agent「领取目标」落为一条目标方案，由目标负责人逐条审核

日期：2026-09-08 · 状态：已采纳 · 关联：0003（Agent 权限 = 所有者 ∩ 授权，待确认操作）、0016（里程碑）、0025（确定性交互）、CONTEXT.md「目标还是任务」

## 背景

用户要的是：「支持 Agent 能够领取目标，自主规划任务，提交系统，由目标负责人审核」。现有模型里目标故意不是可执行对象——没有执行者、没有流程、负责人必须是人（CONTEXT.md「目标还是任务」）。Agent 今天只能一个一个 `create_task`，每个任务各挂一条待确认操作，负责人看到的是零散的十几条，看不出整体方案，也没法"这个要、那个不要"。

## 决策

1. **目标不变成可执行对象。**「领取目标」在语义上落为：Agent 对某个目标提交了一份**目标方案**，方案被目标负责人批准后，Agent 成为其中任务的负责人。目标的负责人仍然是人，目标仍然没有流程与执行记录。
2. **方案是一条待确认操作。** `propose_goal_plan(goal, tasks[], milestones[], rationale)` 生成**一条**动作为 `goal.plan` 的待确认操作，载荷是整套拆解：任务清单（每条带一个方案内的键、标题、说明、类型、预估、计划起止、优先级、所需能力、负责人、上级任务的键、依赖的任务键）、里程碑清单、一段理由。不看授权模式：哪怕「创建任务」授权是直接生效，方案也必须经人审。提交时就把能校验的都校验完（目标可见、授权够、键不重复、依赖与上级都指向方案内的键且不成环、任务类型存在、日期合法），免得人确认了一条注定失败的。
3. **确认人是目标负责人。** 待确认操作的确认人默认是 Agent 的所有者（ADR 0003）；目标方案例外，由**目标负责人**（与组织负责人）确认，通知也发给目标负责人。方案是对目标的承诺，该由对目标负责的人拍板。
4. **逐条勾选，一次落库。** 网页上负责人看到的是整份方案（任务按依赖排好、里程碑按日期排好），可以整体批准、整体拒绝，或勾掉几条再批准。确认接口收 `skip[]`（要跳过的键）与可选的 `assignee_id`（把全部任务改派给别人）。批准后在**一个事务**里创建里程碑、按依赖顺序创建任务（上级先于子任务、前置先于后置）、建立前置关系；跳过的任务不建，指向它的依赖与上级引用一并去掉（依赖跳过的任务的那些照建，只是少了那条前置）。任务默认指派给提案的 Agent（方案里可以逐条写别人），创建者与验收人按 `create_task` 的既有规则。**批准即就绪**：任务建出来直接进「待办」而不是停在草稿——就绪那一步本来要「执行任务」授权，提方案的 Agent 未必有，但这份方案是目标负责人刚批准的，就绪是批准的一部分，所以落库时只在这个事务里给 Agent 一份带「执行任务」的执行者副本。每个对象各自的动态照常记，另记一条 `GoalPlanApplied` 汇总（方案编号、建了哪些任务与里程碑、跳过了哪些），Agent 用 `get_goal_plan_status` 就靠它拿到结果。落库是**幂等**的：这条汇总动态与创建在同一个事务里，再次落同一份方案时先找它，找到就原样返回那次的结果——落库与「标记已确认」是两个事务，后者失败时人再点一次确认，不能把整份方案再建一遍。
5. **拒绝要写理由，和别的待确认操作一样。** 理由是完整句子，Agent 读它决定要不要改方案再提。改方案再提就是新的一条，旧的留在记录里。
6. **不做的事。** 不给方案加"修订"流程（负责人想改内容就拒绝并写清楚，让 Agent 重提）；不让方案跨目标；不让方案直接改目标本身的字段（那是 `update_goal` 的事）；不给人（成员）提供 `propose_goal_plan`——人直接在网页上建任务。

## 被否决的

- **让目标可领取（给目标加执行者与状态）**：破坏「目标还是任务」的分界，进度、成本、验收全都要为目标再造一套。
- **一个任务一条待确认操作**：负责人看不到整体，也做不到"要这几个不要那几个"。
- **批准后逐条调用 `create_task`（每条一个事务）**：中途失败留下半份方案；一次落库才配得上"整体批准"。

## 后果

- 待确认操作多一种动作 `goal.plan`，载荷是多对象；确认接口多两个可选输入 `skip[]`、`assignee_id`。
- `internal/app` 里创建任务与里程碑拆出事务内的实现（`createTaskTx`、`insertMilestoneTx`），方案的批量落库复用它们。
- MCP 新增 `propose_goal_plan`、`get_goal_plan_status`；网页的待确认操作页对 `goal.plan` 显示可勾选的方案清单。
- 新动态 `GoalPlanApplied`；新词 **目标方案**（CONTEXT.md）。
