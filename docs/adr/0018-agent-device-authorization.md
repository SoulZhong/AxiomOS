# ADR 0018：Agent 用设备码接入

日期：2026-09-06 · 状态：已采纳 · 关联：ADR 0003、0014

## 背景

接入一个 Agent 要在网页注册、复制一次性令牌、手工贴进客户端配置。令牌经过剪贴板与聊天窗口，贴错了没有任何提示，接没接上也要自己试。IM 集成已经改成自诊断、逐步引导的向导（ADR 0017 补记二），Agent 接入应当同样：Agent 端一条命令，人在网页里批准，系统自己写配置、自己检查连接。

## 决策

1. **设备码授权**，形态参照 OAuth 2.0 Device Authorization：Agent 端 `POST /agent-auth/device`（公开）拿到一个**设备码**（只有 Agent 端知道）和一个 8 位**验证码**（`ABCD-1234`，人念得出、打得出），有效期 15 分钟；人在网页输入验证码，看到"是什么运行环境、叫什么"，选授权后批准；Agent 端每 5 秒 `POST /agent-auth/token` 轮询，批准后拿到令牌，**令牌只给一次**，之后再问只回状态。
2. **设备码绑定的是 Agent 身份，不是人的会话**。批准时系统以批准人为所有者创建一个新的 Agent（走与手工注册同一条路），Agent 的权限仍是所有者权限 ∩ 授权（ADR 0003）；拒绝或过期什么都不创建。批准产生动态 `AgentConnected`。
3. **接入脚本由服务端生成**（`GET /agent-auth/connect.sh?client=`），POSIX sh，只依赖 curl：申请 → 打印「打开 <网址> 输入 ABCD-1234 批准这个 Agent」并尽量拉起浏览器 → 轮询 → 按运行环境写配置（Claude Code 用 `claude mcp add`，没有 CLI 时打印 JSON；Cursor 合并进 `~/.cursor/mcp.json`；Codex 追加到 `~/.codex/config.toml`；自定义客户端只打印）→ 调一次 `whoami` 做连接检查。令牌只写进客户端配置文件，脚本不落日志。
4. **连接检查**用已有的心跳数据：每次带令牌的请求都刷新 `last_seen_at`，MCP 层另记最近调用的工具名（`last_tool`），`GET /agents/{id}/check` 把它们变成一句人话，向导轮询它。
5. 申请表在组织之外（申请时还不知道属于谁），不做行级安全；令牌用服务端密钥加密暂存，交付即清空；后台巡检每分钟把过期申请标掉、删一天前的记录；轮询快于间隔返回 429。

## 代价

- 多一张表、五个接口、一段嵌入的 shell 模板；PowerShell 版本暂不提供（Windows 用 WSL 或手工令牌路径）。
- 各客户端的配置文件格式由脚本维护，客户端改格式要跟着改。

## 被否决的方案

- **npm 包 `axiomos-agent connect`**：多一个发布物与 Node 依赖；服务端生成的脚本随后端一起发版，私有化部署不需要外网。
- **验证码里带用户会话（OAuth 授权码）**：会把 Agent 绑成人的登录身份，违反 ADR 0003 的所有者 / Agent 分离。
- **网页直接展示令牌让人贴**：就是现状；保留为「其他客户端」的手工路径。

## 补记一：并发与枚举（2026-09-06，安全审查）

- **令牌只给一次**这条要靠一条语句保证，不能"先读再写"：领取是 `update … set token_enc=null, token_taken_at=now() where id=$1 and token_enc is not null`，改到一行才算领到；并发的第二次轮询改不到行，只回 `status: approved`。
- **轮询限流**同样合成一条带条件的更新（`where last_polled_at is null or last_polled_at < now() - 5s`），改不到行就 429；并发不能绕过。
- **验证码不能被枚举**：验证码只有 8 位，登录用户按账号与来源地址限次——5 分钟内查不到 10 次就冷却 5 分钟，期间一律回「验证码试得太多了，过几分钟再试。」批准 / 拒绝走同一道限制。计数在进程内（互斥锁 + 定期清理），不引入新组件；多实例部署时每个实例各自计数，仍然把枚举成本抬到不可用。
