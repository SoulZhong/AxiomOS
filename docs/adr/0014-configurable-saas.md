# ADR 0014：可定制的边界——管理策略可配，正确性写死

日期：2026-09-05 · 状态：已采纳

## 背景

AxiomOS 是一套**可高度定制的 SaaS，同时支持私有化部署**，不是给某一家公司做的内部系统。此前若干设计（尤其 ADR 0013 的初稿）把某一种管理方式直接写进了系统，等于替所有客户做决定。需要一条能反复引用的边界，避免同类错误再犯。

## 决策

**凡是"公司怎么管"的规则，都是每个组织可配置的；只有"系统怎么保证算得对、不越权"的规则才写死。**

写死（正确性与安全，客户不可改）：
- 组织隔离与行级安全（ADR 0001）。
- 动态是唯一事实来源，任何写操作都产生动态（ADR 0002）。
- Agent 有效权限 = 所有者权限 ∩ 授权；需确认的授权必须产生待确认操作（ADR 0003）。
- 内核只认状态类型，不认状态名（ADR 0005）；执行记录由执行者自己开启（ADR 0006）。
- 成本归口口径唯一（ADR 0013）。
- 用户可见文案只用词汇表里的词，不造术语（ADR 0007）。

可配置（管理策略，每个组织自己定，系统只给默认值）：
- 协作数据与财务数据的可见性（ADR 0013）。
- 角色与权限的对应关系、团队层级。
- 任务类型与流程定义，含状态、步骤、参与角色、在制品上限。
- 预算是软提醒还是硬限制；是否启用迭代、看板、工作量点数。
- 语言、货币、价格表。
- 术语别名：客户可以把「迭代」显示成「Sprint」、把「目标」显示成「OKR」，但**别名只改显示，不改数据模型与代码标识符**。

判断口径：如果两家客户可能有不同且都合理的做法，它就是策略，要可配置；如果不同做法会让同一个数字在不同页面对不上、或让越权成为可能，它就是正确性，必须写死。

## 代价

- 每加一条策略都要加设置界面、默认值、私有化升级路径和一句人话解释。
- 组合数量增加，测试要覆盖默认值加至少一个非默认组合。

## 被否决的方案

- **全部写死**：交付快，但每个客户都要改代码，SaaS 无法规模化。
- **全部可配**：包括正确性规则也开放，会出现同一份数据在不同页面对不上，或者绕过 Agent 权限模型。
