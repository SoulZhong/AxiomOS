# ADR 0013：可见性是每个组织可配置的策略

日期：2026-09-05 · 状态：已采纳 · 关联：ADR 0001、0003、0014

## 背景

系统最初只服务"设目标、做任务"的一线场景，所有列表和统计都是全组织的：`CostStats` 把全组织的执行记录全量读出来算，任何成员打开运营总览都能看到公司全部的钱。要服务的人群扩大到 CEO 与董事长、事业部负责人、各级 Leader、普通员工与运营管理人员后，"看多少"必须成为一等概念。

关键在于：**看多少是管理策略，不是系统正确性**。不同客户的文化差别很大，有的要求全员透明，有的要求部门之间严格隔离，财务数据尤其如此。本系统是可高度定制的 SaaS 且支持私有化部署（ADR 0014），因此不能替客户把这条规则写死。

## 决策

引入**范围**（`Scope`）与**共享边界**（`SharingBoundary`）两个概念，并把可见性做成**每个组织可配置的两项策略**，系统只给默认值。

### 共享边界

团队树上的任意一个团队都可以被标记为**共享边界**（`Team.is_boundary`）。一个成员的**可见域**这样算：从他所在的团队沿上级一路向上，找到**最近的**那个被标记为边界的团队（他自己所在的团队也算），可见域就是**那个团队的整棵子树**；一路向上都没有边界时，可见域是全组织。属于多个团队时取并集。

这一条就能表达客户的各种诉求：

- 三个事业部互不共享、事业部内共享：把三个事业部分别标为边界。前端组的人看到整个事业部（含市场部），事业部之间互相看不到。
- 事业部下的几个子公司互不共享、子公司内多级共享：把每个子公司标为边界；事业部直属的人最近边界是事业部，因此能看到下面所有子公司，子公司之间互相看不到。
- 不标记任何边界 = 全组织共享；每个团队都标记 = 只看自己团队及下级。

### 两项策略

| 策略 | 取值 | 默认 |
|---|---|---|
| `collaboration_visibility` 协作数据（目标、任务、看板、甘特图、迭代、动态、待领取） | `org` 全员可见 / `boundary` 按共享边界 / `team_tree` 只看自己团队及下级 | `org` |
| `finance_visibility` 财务数据（成本、用量、预算、Agent 成本） | `org` / `boundary` / `team_tree` | `team_tree` |

`boundary` 是另外两者的推广，实现上只需一套算法。范围选择器列出的可选范围与每一档能否看财务，都由当前组织的策略与边界标记算出来（`GET /auth/me` 的 `scopes[]`）。请求超出可见域时拒绝，理由是完整中文句子，并说明是哪条策略与哪个边界导致的。

### 跨边界的例外

- **组织负责人**永远看全部。
- **「查看全部成本」**（`view_all_cost`）：跨边界看财务数据。
- **「查看全部工作」**（`view_all_work`）：跨边界看协作数据。给 CEO、运营与审计岗用。
- 内置角色**「运营」**同时持有这两项，只读性质。

### 成本归口不做成可配置

一条执行记录的成本算在执行者所属团队头上；执行者是 Agent 时算在其所有者所属团队；没有团队的算「未分组」。这是"算得对"的问题而不是管理策略，全系统必须唯一，否则同一个数字在不同页面对不上。

## 代价

- 组织设置多了两项开关加一个团队上的边界标记，文案必须说人话，并且要能预览"某个人实际能看到哪些团队"。
- 边界标记改动会让一批人的可见范围立刻变化，属于预期行为，但要记进动态。
- 所有列表与统计接口都要接受范围参数，`CostStats` 这类全量扫描要按范围裁剪。
- 策略从 `org` 收紧到 `team_tree` 时，历史上已经看过的数据会突然看不到，属于预期行为。

## 被否决的方案

- **把某一种策略写死**：等于替所有客户决定管理方式，与本系统"高度可定制"的定位冲突。
- **角色上逐个配置可见范围**：最灵活但要逐个维护、容易配错，新人进团队不会自动生效；共享边界跟着组织结构走，进了团队自动生效。
- **只做"自己团队及下级"一种收紧方式**：表达不了"事业部内共享、事业部之间不共享"，而这是多事业部客户最常见的诉求。
