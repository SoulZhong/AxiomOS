# 动态（只增不改的变化记录）是系统骨架

系统需要审计（谁的 Agent 在何时做了什么、花了多少）、通知、对外 Webhook、成本统计和甘特图等多种视图，且 Agent 是主要操作者，操作量远大于传统人工系统。我们决定把每一次状态变化记录为一条不可更改的动态（代码里叫 `DomainEvent`），只增不改；通知、Webhook、统计与所有视图均从动态派生，而不是各自在业务代码里散落触发。

## Considered Options

- **普通增删改 + 独立审计表 + 各处手动发通知**：起步快，但每加一个消费者（新 IM、新报表）都要回到业务代码里补一处触发，审计与真实状态会漂移。
- **完整事件溯源（当前状态完全由回放得出）**：一致性最强，但心智负担大，查询路径复杂。
- **动态为一等实体 + 当前状态表同事务写入（选定）**：动态是唯一可信来源，当前状态表只是为查询服务的投影；派生消费者只订阅动态。

## Consequences

- 任何写操作必须产生动态，没有动态的写入视为 bug。
- 动态在组织内永久保留；组织注销为软删除，动态不物理删除。
- 价格表变化不会改写历史成本，因为成本是按当时价格表版本从用量动态折算的。
