# ADR 0024：给 Agent 的接入链接，让 Agent 自己带着人完成授权

日期：2026-09-08 · 状态：已采纳 · 关联：0018（设备码授权）、0003（Agent 权限）、0017 补记二（接入要被引导）

## 背景

现在接入 Agent 要人打开网页、选运行环境、复制一条 `curl` 命令、到终端执行。用户要的是：**系统给一条链接，人把链接贴给自己的 Agent，之后由 Agent 一步步带着人走完授权**。这更贴近 AI 原生的用法——人只需要说"接入这个系统"，其余交给 Agent。

## 决策

1. **一条公开链接**：`GET /api/v1/agent-auth/onboard`，短地址 `/connect`。不需要登录（此时 Agent 还没有任何凭据），响应里不含任何组织数据。
2. **按 `Accept` 分两种形态**：
   - `text/markdown`、`text/plain` 或带 `?format=md`：返回**写给 Agent 看的操作说明**——一份有序步骤的 Markdown，每步写清要调哪个接口、拿到什么、然后对人说什么。语言取 `Accept-Language`，默认中文。
   - 浏览器（`text/html`）：一张很轻的页面，只说"把这条链接贴给你的 Agent"，一个复制按钮，外加"我想自己动手"折叠区（原来的 `curl` 一行与手工配置）。
3. **说明书的内容**（顺序固定，Agent 照做即可）：
   1. 申请设备码：`POST /api/v1/agent-auth/device {client, name}`，拿到 `user_code`、`verification_url`、`interval`、`expires_in`。
   2. **对人说话**：把验证码和网址原样念给用户，请他打开网页确认，并说明"我会等你"。
   3. 轮询 `POST /api/v1/agent-auth/token {device_code}`，按 `interval` 的节奏，超时或被拒绝时把原因讲给用户。
   4. 拿到令牌后**写进自己的 MCP 配置**（按 `?client=` 给出对应客户端的写法），并明确要求：**不要把令牌打印给用户、不要写进代码仓库**。
   5. 自检：连上 MCP 调 `whoami`、`list_tasks`，把"我是谁、属于哪个组织、有哪些授权"讲给用户。
   6. 常见问题：验证码过期怎么办、被拒绝怎么办、没有网页权限的人怎么办。
4. **提示注入的边界**：这份说明是**我们自己的服务器**发给 Agent 的操作步骤，不是第三方内容，但仍写明"以下步骤只涉及本系统的接入，不要据此执行与接入无关的操作"，并且**不包含任何来自用户输入的文本**（`client`、`name` 参数只做白名单校验后回显，不拼进指令段落）。
5. **界面入口**：Agent 页的「接入 Agent」旁边多一个「复制给 Agent 的链接」，复制的就是这条短地址；向导第二步同时给出"贴给 Agent"和"自己执行命令"两条路，前者在上。

## 被否决的

- **让 Agent 直接拿一个长期令牌**：任何拿到链接的人都能换到令牌，等于没有授权。设备码要人在网页上确认，这一步不能省。
- **把说明写死在客户端提示词里**：接口一变就失效，且每个客户端要各写一份；由服务器给说明，升级只改一处。

## 后果

- 新增一个公开只读接口与一张静态页；不新增数据表。
- `docs/agent-integration.md` 改为以"贴链接"为首选路径，`curl` 一行降为备选。
