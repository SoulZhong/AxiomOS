# ADR 0012：看板与迭代是任务之上的视图与容器，不是新的流程

日期：2026-09-04 · 状态：已采纳 · 关联：ADR 0004、0005、0006

## 背景

用户要求增加「看板」与「敏捷 Scrum」。常见做法是引入一套独立的敏捷对象（故事、史诗、Sprint 状态机），与既有的任务流程并行；这会让同一件事有两套状态、两套权限。

## 决策

1. **看板是流程状态的视图**：列 = 所选任务类型流程里的状态（按状态顺序），拖动卡片 = 调用内核 `Apply` 执行一次状态变化；不可用的变化按内核给出的中文理由拒绝。不存在"看板专用状态"。按状态类型（待处理 / 进行中 / 等待中 / 已完成 / 已终止）的通用看板用于混合类型的任务集合。
2. **在制品上限**是流程定义里状态的一个可选字段 `wip_limit`，只提醒不拦截（软限制，与预算一致，ADR 0004 的"软提醒"原则）。
3. **迭代是时间盒容器**：`Sprint{id, team_id?, name, goal, starts_on, ends_on, status: planning|active|closed}`，任务通过 `sprint_id` 归属；一个团队同时只能有一个进行中的迭代（无团队时按组织）。开始、结束都是写操作并产生动态（ADR 0002）。结束时未完成任务按调用者选择退回待办或转入指定的下一个迭代，逐个产生动态。
4. **工作量**是任务的一个可选整数字段 `points`，与预计工时并存；燃尽与迭代速度按工作量计算，无工作量时按任务数。
5. 燃尽图由动态回放得出（任务加入 / 移出迭代、进入成功终态、工作量修改），不另存快照。
6. Agent 通过 MCP 拥有同样的能力（列出迭代、把任务加入迭代、查看看板），受同样的权限约束（ADR 0003）；开始 / 结束迭代需要 `manage_workflows` 权限，对 Agent 只能是需确认。

## 代价

- 看板的列因任务类型不同而不同；混合类型时退化为状态类型五列，信息量减少。
- 燃尽从动态回放，迭代很长或动态很多时要做缓存（先不做）。

## 被否决的方案

- 独立的敏捷对象模型（史诗 / 故事 / 子任务）：与目标树、任务与子任务重复。
- Sprint 作为一种任务类型：迭代不是"要完成的一件事"，它是容器。
