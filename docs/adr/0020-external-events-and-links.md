# ADR 0020：外部事件触发流程迁移与外部链接

日期：2026-09-06　状态：已接受

## 背景

研发类任务的真实进度在代码平台上：PR 打开、评审、合并，CI 成败。人和 Agent 都不该手动搬状态。Kaneo 用「集成事件 → 目标列」的规则做到了这一点（`docs/design/sources/kaneo.md` §3），我们的流程是状态机，需要把它表达成迁移的触发条件。

## 决定

1. **流程定义扩展**（ADR 0005 的迁移条件）：迁移可以声明 `triggered_by: {source: "git", event: "pr_opened"|"pr_ready"|"pr_merged"|"pr_closed"|"ci_failed"|"ci_passed"}`。外部事件到达时，若任务当前状态有一条这样的迁移且其它前置条件满足，系统以「外部事件」为执行者走该迁移，动态写「PR #12 合并，任务进入待验收」；前置不满足时写一条说明动态并不迁移。触发条件由组织在流程定义里配置（可定制），触发时的状态类型语义写死。
2. **外部链接**：任务可挂外部链接 `{provider, kind: pr|issue|doc|design|other, url, title, external_id, status, updated_at}`。代码平台的链接由 webhook 自动创建与更新（PR 状态 open / draft / merged / closed），其它链接手工添加。任务详情③段显示，卡片显示 PR 状态小标。
3. **平台接入**：GitHub、GitLab、Gitee 走与 IM 集成同一套提供方注册表与接入向导（`Provider` 增加 `WebhookHandler` 能力）：组织设置新增页签「代码平台」，步骤为选平台 → 填凭据（应用 / 令牌）→ 检查（能读仓库、webhook 已建、签名正确）→ 选仓库 → 完成。任务与 PR 的关联规则：PR 标题或分支名含 `#123`（任务序号）或描述含任务链接。
4. **外部操作者**：由外部事件产生的动态与执行记录记录来源与外部用户名（如 GitHub 登录名），若该外部用户绑定了本系统成员则显示成员。
5. **不做**：不做代码托管、不做 CI 配置、不在系统里评审代码。

## 后果

- 新表：代码平台配置（复用 IM 集成的配置表形态）、外部链接、外部身份（复用 `external_identities`，kind=git_user）、webhook 事件去重。
- 流程定义 JSON 新增字段，旧定义不受影响。
- 外部事件走与 Agent 相同的授权检查路径，不能绕过状态机。

## 补记一：外部输入只信到该信的程度（2026-09-06，安全审查）

- **接口地址与代理地址过出网守卫**（同 ADR 0019 补记一）：企业版的 `api_base` 由组织自己填，托管场景下不能指向内网——那会带着访问令牌去打内网服务。私有化部署接内网 GitLab 时设 `AXIOMOS_ALLOW_PRIVATE_EGRESS=1`。
- **回调验过签还要看仓库**：载荷里的仓库必须是这个组织在 `code_repos` 里接进来且还启用着的，否则什么都不改，只在结果里回一句说明（不报 500，代码平台不该因此重试）。密钥万一泄露，也不能拿一个没接入的仓库伪造 PR / CI 事件推进任务。
- **自动建的外部链接必须落在这个平台自己的域名上**（按提供方的控制台地址反推，企业版跟着接口地址走）；手工加的链接只认 http(s)，不许带用户名密码或控制字符。
- **回调密钥默认不回显**：`GET /org/code-platform` 只说它设没设，要看值得显式来一次 `?reveal=secret`——那一次 `Cache-Control: no-store` 并产生动态「查看了回调密钥」。`PUT` 带 `rotate_webhook_secret: true` 可以随时换一把。
- **配置变更的动态只记字段名**：接口地址、用户名、代理地址都可能暴露内网拓扑，动态里只留改了哪些字段，不留值。
