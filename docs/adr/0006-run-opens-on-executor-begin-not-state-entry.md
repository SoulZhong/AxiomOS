# 执行记录在执行者自己开始时才开始，而不是在进入"进行中"状态时

原型验证（`prototypes/workflow-engine.prototype.html`）发现：若执行记录（`Run`）随"进入进行中状态"自动开始，那么设计完成交接给开发时，执行记录会由触发交接的设计者创建，执行者被记为任务负责人（小李），而真正干活并上报消耗的是小李的 Agent；参与角色空缺时更会出现"阶段进行中却无人负责"的空窗。我们决定：**执行记录只在任务负责人（或他的 Agent）自己进入阶段、从待领取任务领取、或显式点「开始执行」时开始**；由他人交接进入的进行中状态不开始执行记录。离开进行中状态时结束当前执行记录。

## Consequences

- "进行中"只表示阶段在进行；"有人在干"由是否存在进行中的执行记录表达。任务处于进行中状态而没有执行记录是合法的中间态。
- Agent 必须先开始执行才能上报消耗；没有进行中的执行记录，上报即拒绝。
- 一个阶段可以有多段执行记录（提问等待前后各一段）。统计按段求和，不假设"一个阶段一段记录"。
- 人可以不开始执行记录直接完成一个阶段，代价是该阶段没有周期与成本记录；这是刻意允许的，不强迫人打卡。
- 状态类型里原来的"初始"改为"未开始"并允许标记可领取，因为草稿与待办的区别只在能否领取。
