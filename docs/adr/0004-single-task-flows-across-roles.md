# 一个任务在角色间流转，而不是按阶段拆成多个任务

研发类工作（需求：设计 → 开发 → 测试 → 上线）天然经过多个角色。我们决定用**一个任务**承载整个流转：流程的每一步可以把任务负责人换成任务类型规定的某个参与角色（`Participant`，如开发、测试）上的人；该位置空着时任务进入待领取任务并要求对应角色；每个"进行中"阶段有各自的执行记录，成本按阶段归到各自的执行者。

## Considered Options

- **按阶段拆成多个任务（设计任务、开发任务、测试任务）并用前置关系串联**：每个任务模型简单，但"一个需求"变成了 N 条记录，进度、Bug 关联、甘特图和给 Agent 的任务说明都要跨记录拼装；非研发场景（一件事经三个人的手）也会被迫拆碎。
- **单任务流转 + 参与角色（选定）**：任务身份稳定，执行记录提供阶段粒度的成本与周期统计，流程完全靠声明描述，Agent 问一下"下一步能做什么"就能继续。

## Consequences

- 执行记录必须记录它属于哪个阶段；"一个任务同一时刻至多一段进行中的执行记录"的不变量保持不变。
- Bug 不是需求的子任务，而是通过「发现于」关联平级挂在需求上；"需求上线前须无未关闭 Bug"由流程中「测试通过」这一步的前提条件声明，不写死在内核。
- 流程的每个状态可以带可选的进度权重，让多阶段任务的进度不再是非 0 即 100。
