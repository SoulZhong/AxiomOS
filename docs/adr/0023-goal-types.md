# ADR 0023：目标有类型，类型是组织自己的词表，不带流程

日期：2026-09-07 · 状态：已采纳 · 关联：0014（可定制边界）、0004/0005（任务类型与流程）、0022（路线图）

## 背景

用户要求目标能分类：产品、项目、经营目标等等。现在目标只有层级与团队，路线图上一眼看不出"这是一条产品线"还是"这是一次经营冲刺"，泳道也只能按团队或负责人切。

## 决策

1. **目标类型是组织自己维护的词表**（`goal_types`：名称、颜色、图标、排序、是否停用），不是写死的枚举。不同公司叫法不同（产品线、战役、项目、主题），属于"公司怎么管"，按 ADR 0014 应当可配。
2. **类型只做分类与显示，不带任何行为**：
   - **没有流程**。任务类型决定走哪套状态机（ADR 0004、0005），目标类型**不决定任何东西**：目标本来就没有流程，进度靠汇总、达成靠人确认（ADR 0016）。这条写死，不给"给目标类型配流程"的口子，否则目标会退化成大任务。
   - 不决定权限、不决定成本归口、不决定可见范围。
   - 唯一允许的附带信息是**默认时间粒度**（新建这个类型的目标时预填，比如经营目标默认到季度、项目默认到周），仍可逐个目标改。
3. **内置三种，可改可加可停用**：产品、项目、经营目标。停用后新建时选不到，已有目标照常显示；**有目标在用的类型不允许删除**，只能停用（与团队、能力标签同一套规则）。
4. **目标的类型可空**，显示为「未分类」。历史目标全部为空，不做猜测性回填。
5. **哪里用它**：新建目标与目标详情（就地编辑）· 目标树上的一枚小标签 · 路线图的分组多一档「按类型」、条的颜色可按类型着色（开关，默认按状态）· 目标筛选 · 组织概览按类型看成本与进度 · 导出。
6. **设置入口**：组织设置新增「目标类型」页签，与能力标签、价格表同级；改名即改显示，不动历史（沿用术语别名只影响显示的原则）。

## 被否决的

- **写死的枚举**：三个词写死等于替所有客户决定他们怎么分类，违反 ADR 0014。
- **给目标类型配流程或必填字段**：那是任务类型的职责；目标一旦有了流程，"能不能指派给一个人"这条区分目标与任务的判定规则就废了（CONTEXT.md「目标还是任务」）。
- **用标签代替类型**：一个目标同时是"产品"和"项目"没有意义，多选会让路线图分组失去确定性。要多维度用团队与负责人，那两个维度已经有了。

## 后果

- 新表 `goal_types` 与 `goals.type_id`（迁移 0021），旧目标为空。
- 目标视图新增 `type{id,name,color,icon}|null`。
- 路线图分组新增一档，条着色新增一个开关。
- 演示组织按内置三种预置，并给现有目标各指一个合适的类型。
