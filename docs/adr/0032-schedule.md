# ADR 0032：日程是目标、任务、里程碑与外部日历的一种看法

日期：2026-09-10 · 状态：已采纳 · 关联：0013（可见范围）、0014（什么可配）、0017（外部目录与提供方插件）、0019（通知外发）、0021 / 0022（路线图是目标的一种看法）、任务 #21

## 背景

目标「日程：每个用户都能方便的看到自己的日程安排」要的是三件事：与飞书、企业微信、Google Calendar 同步；不同粒度的日程；能看到目标、任务、会议等一切占据自己时间的安排，并且能集中了解团队的。

系统里已经有的东西都带时间：任务有计划起止与截止日，目标有计划起止，里程碑有到期日；缺的是外部日历里的会议，以及把这四样按"我的一天 / 一周 / 一个月"摆在一起看的地方。

## 决策

### 1. 日程不是新对象，是四类来源的读时聚合

同路线图（ADR 0021）：**日程**是目标、任务、里程碑与外部日历的一种看法，不新增可执行对象，不给日程项加状态、负责人或流程。一条**日程项**只在读的时候拼出来，来源四类：

| 来源 | 时间从哪来 | 画成 |
|---|---|---|
| 任务 | 计划开始到计划结束是一段；截止日单独一枚标记 | 一段（有起止）或一枚（只有截止） |
| 目标 | 计划开始到计划结束 | 一段，淡一级（目标是背景，不是当天要做的事） |
| 里程碑 | 到期日 | 一枚菱形（沿用路线图） |
| 外部日历 | 会议的起止（含全天） | 一段，带来源标记（飞书 / 企业微信 / Google） |

前三类不落库；外部日历事件是同步来的**副本**，落 `calendar_events`（见第 4 条）。

### 2. 三档粒度写死：日 / 周 / 月

只开日、周、月三档，不做议程列表、不做年视图；周从周一开始（与路线图一致）。三档是表达方式，不做成可配置词表（ADR 0014 的边界）。

### 3. 谁的日程、谁看得见

- **我的日程** = 我负责的任务 + 我负责的目标（及其里程碑）+ 我绑定的外部日历。Agent 负责的任务算在它所有者的日程里（Agent 替人做事，占的是人的时间安排）。
- **团队日程** = 组织树上任一节点（含下级团队）全部成员的安排，加上归口到这些团队的目标与它们的里程碑（负责人不在团队里也算——目标是团队的事），合在一张表里看，每条带谁的名字，只读；树顶上多一档整个组织、写组织自己的名字（按可见域截），默认节点是自己所属的最近那个团队，不属于任何团队就看整个组织。谁能看谁照 ADR 0013 的协作数据策略；财务信息不进日程。
- **外部日历的隐私边界**：自己的会议看得到标题；别人的会议只画成「忙」（一段没有标题的块）。「团队内可见会议标题」是管理策略、可以做成组织可配（ADR 0014），本期先不开这个开关。

### 4. 外部日历只读同步，提供方是插件

- `internal/directory` 的注册表加第四种能力 **`CalendarProviders()`**，与读组织结构、发消息、代码平台三个列表互不重叠；新增一家日历仍然只是新增一个文件。接口：`Test(配置)`、`ListEvents(配置, 成员在该平台的身份, from, to)`；不提供写入。
- **组织级连接**：飞书与企业微信用企业应用凭据——同一提供方在 IM 集成里已经填过的凭据直接沿用，这里只补日历专用字段（企业微信的企业日历 ID）；与外部目录同一套加密与出网守卫，凭据不回显，改配置的动态只记字段名。Google 用组织登记的 OAuth 客户端，**每个成员自己授权**一次（授权后的刷新令牌按成员加密存）。
- **成员如何对上外部账号**：飞书 / 企业微信沿用外部目录的身份映射（`external_identities`）；Google 由成员自己授权时绑定。
- **同步**：后台每 15 分钟一轮，拉过去 7 天到未来 60 天，按 `(org, provider, member, external_id)` 幂等写入 `calendar_events`；只存忙闲、标题、起止、全天、链接，不存参会人与正文。失败原因记在连接上，界面直接显示那句话。
- **不回写**：不创建、不改、不删外部日历里的任何东西；也不把 AxiomOS 的任务推到外部日历（那是另一件事，另议）。

### 5. 接口

- `GET /schedule?from=&to=&who=me|<member_id>|<team_id>`：返回这段日期里的日程项（平铺、按日期排好，界面自己按天或按人分桶），每项带来源类型、对象 ID、标题、日期或起止、全天、状态摘要（任务的状态与进度、目标的状态、里程碑是否已达到、会议的来源），点得开。范围最长 62 天。
- MCP `get_my_schedule(from, to)`：Agent 看它所有者的日程，只读，给它用来判断「人什么时候有空、这周排了什么」。
- 外部日历：组织设置下连接 / 测试 / 手动同步 / 断开四个接口；个人的 Google 授权走一对 OAuth 回调接口。

### 6. 界面

- 侧栏新增入口**「我的日程」**（与「我的工作」同级，第七个入口；起初做成「我的工作」的页签，所有者当天就要求独立出来——日程是人每天要看的东西，不该藏在页签里；旧地址 `/?tab=schedule` 自动跳到 `/schedule/`）：顶部日 / 周 / 月三档（记住上次）、今天按钮、前后翻页；四类各有画法与颜色；点一条跳到对应详情；「我的 / 团队」切换，团队从组织树上选节点、默认自己最近的团队，整个团队的安排合在一张表里、每条带名字。空态一句「这周还没有安排」。
- 组织设置下新增页签**「外部日历」**：三家提供方的连接、同步状态、手动同步、断开，走接入向导那套自诊断分步（DESIGN.md §「引导式接入」）。
- 个人设置里一枚「连接我的 Google 日历」。

### 7. 不做的事

- 不创建会议、不发邀请、不改外部日历。
- 不给日程项拖拽改时间：任务的计划起止在任务页或任务甘特图改，目标的在路线图改。
- 不加新的提醒通道：逾期与到期提醒沿用通知外发（ADR 0019）。
- ~~不做 iCal 订阅导出（有需要再议）。~~ 补记一改了这条：两个方向的订阅都做了。

## 被否决的

- **把日程做成新对象（可创建的"日程项"）**：那就是又一个日历软件；组织已经有日历软件，缺的是把工作安排和会议放在一起看。
- **只做 iCal 订阅地址让用户在外部日历里看 AxiomOS**：方向反了——目标要的是在 AxiomOS 里集中看，而且团队日程做不了。（补记一把它作为「补充」而不是「替代」做了：集中看仍在 AxiomOS，订阅链接只是让人在自己习惯的日历里也能看到。）
- **回写外部日历**：多一倍的一致性问题，先不做。

## 后果

- 新表 `org_calendars`（组织级连接与最近一次同步的结果）、`calendar_identities`（成员与外部账号的绑定，Google 的令牌在这里）、`calendar_events`（同步来的副本）；迁移 0025。
- `internal/directory`：`Calendar` / `OAuthCalendar` / `CalendarDiagnoser` 接口、`Provider.NewCalendar` 与 `CalendarProviders()`（`calendar.go`）；飞书与企业微信在各自文件里加 `NewCalendar`，Google 是新文件 `googlecal.go`；测试用 `FakeCalendar`。
- `internal/app/schedule.go`：聚合；`internal/app/calendar.go`：连接、同步、授权。
- HTTP：`/schedule`、`/org/calendars/{provider}` 及其 `test` / `sync`、`/me/calendars`、`/me/calendars/google/callback`；MCP：`get_my_schedule`（`docs/api.md`「日程与外部日历」）。
- 网页：「我的日程」、「组织设置 · 外部日历」、个人设置的连接入口；DESIGN.md 新节；快捷键 `g s`。
- 新词（CONTEXT.md）：日程、日程项、外部日历。

## 补记一（2026-09-10）：日历的通用协议——两个方向的订阅

所有者问：组织级要管理员配，个人能不能自己设置？日历有没有「只要订阅就行」的协议？有，就是 iCalendar 订阅（ICS / webcal）；CalDAV 是双向的、要账号密码、飞书与企业微信不支持，我们只读，用不上。于是加两样东西，都不需要管理员：

1. **日历订阅链接（进）**：`internal/directory` 新增提供方 `ics`，是 `CalendarProviders()` 的第四家，多一个标志 `SelfServiceCalendar`——不需要组织配置，成员在个人设置里贴一条自己日历软件给的私密 `.ics` / `webcal` 链接就连上（Google 的「iCal 格式的私密地址」、Outlook 的「发布日历」、Apple iCloud、飞书的订阅链接都是这种）。链接就是密钥：加密存在成员绑定里、不回显、换链接就是换密钥；过出网守卫（只许 https，webcal 转成 https，内网按 `AXIOMOS_ALLOW_PRIVATE_EGRESS` 放行）。第一次连接时先拉一次证明能读（不是 ICS 的网页链接直接拒），然后立刻同步；之后走同一条 15 分钟一轮的后台巡检（连接行按提供方自动建一行，空凭据、启用）。重复事件按 RRULE 在服务端展开（FREQ / INTERVAL / COUNT / UNTIL / BYDAY / BYMONTHDAY / BYMONTH，EXDATE 排除，RECURRENCE-ID 覆盖），忙闲照 TRANSP 与 Outlook 的忙闲扩展字段，取消的不要。每个成员自己的同步结果记在绑定行上（`last_sync_at / last_status / last_error`），个人设置里直接看那句话。自助提供方不出现在组织设置的「外部日历」页。
2. **对外订阅源（出）**：`GET /api/v1/feeds/{token}.ics` 公开接口，token 就是密钥（一人一条，`calendar_feeds`），谁拿到都能读这个人负责的任务（计划起止与截止）、目标、里程碑，写成全天的 VEVENT（`TRANSP:TRANSPARENT`，不占忙闲），窗口过去 30 天到未来 180 天，按拉取时现算，`X-PUBLISHED-TTL:PT15M`。不含外部日历同步来的会议——那本来就在他的日历里。个人设置里生成 / 换一条 / 停用；换与停用都过一次后果确认，因为旧链接立刻失效。

第 3 条「谁的日程、谁看得见」不变：订阅链接进来的会议照旧只有自己看得到标题；对外订阅源按他本人的可见范围算。第 4 条「提供方是插件」不变：ICS 也只是新增一个文件。

## 补记二（2026-09-10）：CalDAV 账号——企业微信、iCloud 这类不给订阅链接的个人日历

所有者问个人的企业微信日程怎么进来。企业微信不给个人日历的订阅链接，给的是「同步至其他日历」：CalDAV（服务器 `caldav.wecom.work` + 帐号 + 现取的密码）与 Exchange ActiveSync；组织级的企业微信接口又只读得到自建应用自己建的那本企业日历，成员的个人日程碰不到。于是加第二种自助提供方：

- **`caldav`（CalDAV 账号）**：`SelfServiceCalendar`，字段是服务器、账号、密码（保密）。只读：PROPFIND 三步发现（principal → calendar-home → 每本装 VEVENT 的日历），REPORT `calendar-query` 按时间段拉，拿回来的仍是 iCalendar 文本，交给 `ics.go` 解析与展开重复规则；填的本身是一本日历的地址时直接查它。服务器地址过出网守卫；三个字段整组加密存在成员绑定里，不回显；网络错误文本抹掉地址。401 / 403 →「账号或密码不对…」，回网页 →「这个地址不是 CalDAV 服务器…」，没有日历 → 整句说明。
- 企业微信之外，Apple iCloud（`https://caldav.icloud.com` + App 专用密码）也走它。Google 不支持账号密码，仍走订阅链接或组织级的 Google 日历。
- 不做 Exchange ActiveSync：手机系统日历那条路，协议重、又不是标准 HTTP 文本。
- 已知的软肋：企业微信的密码「每次现取」，官方没说旧密码何时失效；失效时同步在个人设置里显示失败原因，人重新取一个填进去即可。
