# ADR 0032：日程是目标、任务、里程碑与外部日历的一种看法

日期：2026-09-10 · 状态：已采纳 · 关联：0013（可见范围）、0014（什么可配）、0017（外部目录与提供方插件）、0019（通知外发）、0021 / 0022（路线图是目标的一种看法）、任务 #21

## 背景

目标「日程：每个用户都能方便的看到自己的日程安排」要的是三件事：与飞书、企业微信、Google Calendar 同步；不同粒度的日程；能看到目标、任务、会议等一切占据自己时间的安排，并且能集中了解团队的。

系统里已经有的东西都带时间：任务有计划起止与截止日，目标有计划起止，里程碑有到期日；缺的是外部日历里的会议，以及把这四样按"我的一天 / 一周 / 一个月"摆在一起看的地方。

## 决策

### 1. 日程不是新对象，是四类来源的读时聚合

同路线图（ADR 0021）：**日程**是目标、任务、里程碑与外部日历的一种看法，不新增可执行对象，不给日程项加状态、负责人或流程。一条**日程项**只在读的时候拼出来，来源四类：

| 来源 | 时间从哪来 | 画成 |
|---|---|---|
| 任务 | 计划开始到计划结束是一段；截止日单独一枚标记 | 一段（有起止）或一枚（只有截止） |
| 目标 | 计划开始到计划结束 | 一段，淡一级（目标是背景，不是当天要做的事） |
| 里程碑 | 到期日 | 一枚菱形（沿用路线图） |
| 外部日历 | 会议的起止（含全天） | 一段，带来源标记（飞书 / 企业微信 / Google） |

前三类不落库；外部日历事件是同步来的**副本**，落 `calendar_events`（见第 4 条）。

### 2. 三档粒度写死：日 / 周 / 月

只开日、周、月三档，不做议程列表、不做年视图；周从周一开始（与路线图一致）。三档是表达方式，不做成可配置词表（ADR 0014 的边界）。

### 3. 谁的日程、谁看得见

- **我的日程** = 我负责的任务 + 我负责的目标（及其里程碑）+ 我绑定的外部日历。Agent 负责的任务算在它所有者的日程里（Agent 替人做事，占的是人的时间安排）。
- **团队日程** = 团队成员各自的日程并排看，只读。谁能看谁照 ADR 0013 的协作数据策略；财务信息不进日程。
- **外部日历的隐私边界**：自己的会议看得到标题；别人的会议只画成「忙」（一段没有标题的块）。「团队内可见会议标题」是管理策略、可以做成组织可配（ADR 0014），本期先不开这个开关。

### 4. 外部日历只读同步，提供方是插件

- `internal/directory` 的注册表加第四种能力 **`CalendarProviders()`**，与读组织结构、发消息、代码平台三个列表互不重叠；新增一家日历仍然只是新增一个文件。接口：`Test(配置)`、`ListEvents(配置, 成员在该平台的身份, from, to)`；不提供写入。
- **组织级连接**：飞书与企业微信用企业应用凭据——同一提供方在 IM 集成里已经填过的凭据直接沿用，这里只补日历专用字段（企业微信的企业日历 ID）；与外部目录同一套加密与出网守卫，凭据不回显，改配置的动态只记字段名。Google 用组织登记的 OAuth 客户端，**每个成员自己授权**一次（授权后的刷新令牌按成员加密存）。
- **成员如何对上外部账号**：飞书 / 企业微信沿用外部目录的身份映射（`external_identities`）；Google 由成员自己授权时绑定。
- **同步**：后台每 15 分钟一轮，拉过去 7 天到未来 60 天，按 `(org, provider, member, external_id)` 幂等写入 `calendar_events`；只存忙闲、标题、起止、全天、链接，不存参会人与正文。失败原因记在连接上，界面直接显示那句话。
- **不回写**：不创建、不改、不删外部日历里的任何东西；也不把 AxiomOS 的任务推到外部日历（那是另一件事，另议）。

### 5. 接口

- `GET /schedule?from=&to=&who=me|<member_id>|<team_id>`：返回这段日期里的日程项（平铺、按日期排好，界面自己按天或按人分桶），每项带来源类型、对象 ID、标题、日期或起止、全天、状态摘要（任务的状态与进度、目标的状态、里程碑是否已达到、会议的来源），点得开。范围最长 62 天。
- MCP `get_my_schedule(from, to)`：Agent 看它所有者的日程，只读，给它用来判断「人什么时候有空、这周排了什么」。
- 外部日历：组织设置下连接 / 测试 / 手动同步 / 断开四个接口；个人的 Google 授权走一对 OAuth 回调接口。

### 6. 界面

- 侧栏新增入口**「我的日程」**（与「我的工作」同级，第七个入口；起初做成「我的工作」的页签，所有者当天就要求独立出来——日程是人每天要看的东西，不该藏在页签里；旧地址 `/?tab=schedule` 自动跳到 `/schedule/`）：顶部日 / 周 / 月三档（记住上次）、今天按钮、前后翻页；四类各有画法与颜色；点一条跳到对应详情；「我的 / 团队」切换，团队按成员一人一行。空态一句「这周还没有安排」。窄屏只留日与周。
- 组织设置下新增页签**「外部日历」**：三家提供方的连接、同步状态、手动同步、断开，走接入向导那套自诊断分步（DESIGN.md §「引导式接入」）。
- 个人设置里一枚「连接我的 Google 日历」。

### 7. 不做的事

- 不创建会议、不发邀请、不改外部日历。
- 不给日程项拖拽改时间：任务的计划起止在任务页或任务甘特图改，目标的在路线图改。
- 不加新的提醒通道：逾期与到期提醒沿用通知外发（ADR 0019）。
- 不做 iCal 订阅导出（有需要再议）。

## 被否决的

- **把日程做成新对象（可创建的"日程项"）**：那就是又一个日历软件；组织已经有日历软件，缺的是把工作安排和会议放在一起看。
- **只做 iCal 订阅地址让用户在外部日历里看 AxiomOS**：方向反了——目标要的是在 AxiomOS 里集中看，而且团队日程做不了。
- **回写外部日历**：多一倍的一致性问题，先不做。

## 后果

- 新表 `org_calendars`（组织级连接与最近一次同步的结果）、`calendar_identities`（成员与外部账号的绑定，Google 的令牌在这里）、`calendar_events`（同步来的副本）；迁移 0025。
- `internal/directory`：`Calendar` / `OAuthCalendar` / `CalendarDiagnoser` 接口、`Provider.NewCalendar` 与 `CalendarProviders()`（`calendar.go`）；飞书与企业微信在各自文件里加 `NewCalendar`，Google 是新文件 `googlecal.go`；测试用 `FakeCalendar`。
- `internal/app/schedule.go`：聚合；`internal/app/calendar.go`：连接、同步、授权。
- HTTP：`/schedule`、`/org/calendars/{provider}` 及其 `test` / `sync`、`/me/calendars`、`/me/calendars/google/callback`；MCP：`get_my_schedule`（`docs/api.md`「日程与外部日历」）。
- 网页：「我的日程」、「组织设置 · 外部日历」、个人设置的连接入口；DESIGN.md 新节；快捷键 `g s`。
- 新词（CONTEXT.md）：日程、日程项、外部日历。
- 编号说明：0029–0031 已被 ADR 0028 的后续（决定在客户端里答、用量与成本观测、身份与交付物真实性）预留，所以日程用 0032。
