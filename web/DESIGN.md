## 定位

AxiomOS 是一艘星舰的舰桥：整个组织的目标、任务、人和 Agent 都在这块深色的控制台上运转。风格基底是 Linear（密集、精确、克制、无阴影、单一强调色），科幻感来自**材质与仪表**，不来自霓虹与渐变：近黑画布像舷窗外的太空，四级表面像层层抬升的仪表板，细线像面板的接缝，薰衣草蓝像舰桥仪表的指示光，等宽小字像遥测读数。

默认是**深色**（舰桥）。另有一套**浅色模式**（"日间舱室"），同一套语义 token 名只换值，见「浅色模式」一节。品牌页（登录、邀请、后台登录）永远是深色——那是舱外的太空。

## 颜色

- **画布与阶梯**：页面底 `{colors.canvas}`；面板 `{colors.surface-1}`；悬停行、次级按钮、当前导航项 `{colors.surface-2}`；下拉菜单与提示气泡 `{colors.surface-3}`；再抬升一级 `{colors.surface-4}`。层次只靠阶梯和 1px 细线（`{colors.hairline}` → `{colors.hairline-strong}` → `{colors.hairline-tertiary}`），**没有投影**。每个面板顶边加一条 `{colors.edge-highlight}` 内嵌高光，Linear 称之为"像素渲染感"。
- **唯一强调色**：薰衣草蓝 `{colors.accent}`。用于主按钮、当前导航的左侧竖线、焦点环、链接、进度条、甘特图的"今天"线、选中态。悬停变亮 `{colors.accent-hover}`。主按钮和进行中的状态指示灯允许一圈 `{colors.accent-glow}` 微光，这是整套系统里**唯一的发光**。
- **语义色**只表状态，且在深色画布上用"文字色 + 12% 底 + 35% 边"的三件套：未开始=neutral，进行中=accent，等待中=warning，已完成=success，已终止=neutral（终止不是错误），逾期与危险操作=danger。
- **遥测色** `{colors.telemetry}` 只给等宽的读数文字（ID、时间戳、token 数、快捷键），是强调色的浅变体，不是第二个强调色。
- 禁止：第二个饱和色、任何渐变、玻璃拟态、彩色背景大面积铺满、青柠或粉色。

## 字体与字阶

- 界面字体 **Inter**（Linear 自有字体的公开替代），400 / 500 / 600；中文回退 PingFang SC / Hiragino Sans GB / Microsoft YaHei / Noto Sans CJK SC。数字全局 `tabular-nums`。
- 等宽字体 **JetBrains Mono**，只用于遥测读数：ID、时间戳、token、成本明细、快捷键、代码、表头微标签。
- 字阶：页面标题 24px/600 字距 -0.5px；面板标题 16px/500 字距 -0.2px；正文 14px/400 行高 1.5；说明 12px；表头与眉标 11px 等宽、正字距 +0.6px（Linear 的"眉标用正字距做分类标记"）。品牌页大标题 40px/600 字距 -1px。
- 600 只允许出现在页面标题与品牌页标题；正文与按钮不超过 500。

## 间距与圆角

- 4px 基数：2 / 4 / 8 / 12 / 16 / 24 / 32 / 48。面板内边距 16px，面板间距 16px，页面外边距 24px，表格单元格 10px 12px，标签 1px 6px。
- 圆角：标签 4px，导航项 6px，按钮与输入框 8px，面板与抽屉 12px，品牌页大面板 16px，指示灯全圆。不用胶囊按钮。

## 布局

- 外壳：左侧 220px 侧边栏，`{colors.canvas}` 底，右侧 1px `{colors.hairline}`；顶部无全局顶栏；内容区最大 1280px，外边距 24px。
- 侧边栏顶部：舰徽（一个细线绘制的环形轨道 + 圆点）与字标 "AxiomOS" 同一行，下面 11px 等宽眉标显示组织名（如 `DEMO · CNY`），这是"舰桥标识牌"。
- 页面三段式不变：页头（标题 + 一句说明 + 右侧唯一主按钮）→ 统计芯片条 → 面板。
- 断点：≥1200 完整；992–1199 侧栏收成 56px 图标栏；768–991 详情侧栏落到下方；<768 单列，导航变抽屉。

## 浅色模式

- 触发：侧边栏底部的主题切换（系统 / 深色 / 浅色），保存在浏览器；默认跟随系统 `prefers-color-scheme`。切换即时生效，不刷新。

- 对比度底线：`ink-subtle` 在 `surface-1` 上不低于 4.5:1（实测 5.0:1）；语义色文字在各自 10% 底上不低于 4.5:1（success 4.7 / warning 4.9 / danger 4.6——浅色的三个语义色因此比 Linear 的原值再深一档）；`ink-tertiary` 仍不用于必须阅读的文字。
- 实现细节：原始变量叫 `--c-<token>`（`globals.css`），Tailwind 的 `--color-<token>` 通过 `@theme inline` 映射到它们；品牌页根节点带 `data-theme="dark"`，整套深色值在这棵子树上局部重设。SVG / 内联样式里派生的透明度用 `color-mix(in srgb, var(--c-accent) 38%, transparent)`，不写 rgba 字面值。

## Axiom 科幻层（舰桥系统）

科幻感必须**一眼可见**，但来自舰桥仪表的材质与信息密度，不来自霓虹与特效。以下是全站必做的元素，按可见度排序：

1. **舰桥状态栏（全局）**：主内容区顶部一条 32px 高的遥测条，`{colors.surface-1}` 底、底部 1px `{colors.hairline}`，左起等宽 11px 读数：`AXIOM · OPERATING SYSTEM`、`ORG DEMO`、`AGENTS 2/2 READY`（可用用 success 指示灯）、`RUNS 1 ACTIVE`（进行中用呼吸的 accent 指示灯）、`COST TODAY ¥25.07`；右侧 `SYS 16:07:22`（秒级跳动）与主题/语言切换。数据来自现有接口（agents、tasks/mine、stats/cost），30 秒刷新一次。这是"舰桥"最直接的证据，每一页都在。
2. **坐标网格画布**：主内容区画布铺一层极淡的 24px 点阵网格（`{colors.grid-line}`，深色 8% / 浅色 6%），面板盖在网格之上。侧边栏底部保留星点层。
3. **HUD 面板**：面板四角各一枚 6px 细线角标（`{colors.hairline-strong}`，悬停或面板处于活动状态时变 `{colors.accent-border}`）；面板标题前加等宽序号眉标（`01`、`02`…按页面内顺序），标题右侧留遥测位（如条数、更新时间）。
4. **能量线**：页面标题下方一条 1px 线，左段 `{colors.accent}` 到右段透明的渐隐（这是唯一允许的渐变，且只在这里），宽 160px。
5. **状态指示灯**：8px（原 6px），进行中的呼吸 + 微光，可用 Agent 的 success 灯常亮微光。
6. **刻度进度条**：进度条底部每 10% 一道 1px 刻度（`{colors.hairline-strong}`），像仪表刻度；目标树与详情侧栏都用它。
7. **遥测读数**：所有 ID、时间戳、token、成本、快捷键等宽 + `{colors.telemetry}`；数字变化时 200ms 淡入。
8. **雷达空状态**：空状态插画改为雷达扫描（细线同心圆 + 一道 8s 一圈的扇形微光，`prefers-reduced-motion` 时静止），下方一句说明 + 主动作。
9. **甘特图 = 航线图**：时间轴顶部加刻度尺（每天一道细刻度、每周一道长刻度、等宽日期），"今天"是带小三角的 accent 竖线，任务条两端有 1px 端点，目标汇总条像航段。
10. **登录页 = 接近母舰**：见下方「品牌页」一节。不再有自检提示语、不再有打字动画。
11. **舰徽**：轨道环 + 公转点，侧边栏 24px、登录页 64px、空状态 48px。

## 品牌页（登录 / 邀请 / 后台登录）= 接近母舰

意象来自《机器人总动员》：镜头从深空缓缓推向 Axiom 母舰——一艘巨大、洁白、层层甲板都亮着灯的星际邮轮，安静地悬在星海里。登录就是"请求登舰"。画面必须**一眼看出是一艘星舰**，动画必须**慢、稳、有重量感**，像真实的太空镜头。

实现方式是 WebGL 实时场景（ADR 0011，技术依据见 `docs/design/sources/threejs-implementation-notes.md`）。让画面"贵"的八条原则，来自 `docs/design/sources/scifi-web-animation-survey.md`：

1. 光照是主角：一盏暖主光 + 一盏冷轮廓光 + 环境贴图，不用均匀环境光。
2. 亮的东西真的亮：舷窗、船头带、引擎是 HDR 自发光，由 Bloom 泛光，不贴光晕图。
3. 镜头很慢且有惯性；大物体更慢。
4. 后期是薄薄一层：Bloom + 轻微暗角 + 3%–5% 颗粒，不拉满色散。
5. 有深度层次：近景星尘、中景母舰、远景星空与星云，视差各不相同。
6. 一个色调映射（ACES）+ 一个曝光值，全场一致。
7. 没有硬边：星点是软圆，渐变有抖动。
8. 运动由一条时间线统筹。

### 画面构成（自后向前）

1. **深空**：`{colors.canvas}` 底；右上角一团 fbm 噪声星云（靛蓝 → 暖灰紫，贡献不超过 10%，域扭曲、极慢流动）；船尾方向一线**暖色远日**（`--c-sun` #ffd9a0，4%–6%），全站唯一允许的暖色。
2. **星场**：三层 5000 颗软圆星点（远 3000 / 中 1500 / 近 500），尺寸随距离衰减，30% 的星以各自相位、15% 振幅、低于 1.5 Hz 缓慢明暗；鼠标视差按层 0.02 / 0.05 / 0.09，带阻尼。
3. **Axiom 母舰**（原创"Axiom 风格"客轮，≥1024px 时占据视口右侧约 54% 宽、下三分之二高，船头朝右上抬起约 4°）：
   - 流畅的水滴形船体（旋转轮廓 + 压扁截面），船头高大钝圆、船尾收窄，两片宽而扁的后掠推进翼；一条从船尾掠起、在船头后方形成圆顶脊线的上层建筑；小穹顶舰桥与天线；
   - 哑光白 PBR 材质（`#d6dae1`，metalness 0.15，roughness 0.62），暖主光来自船尾方向的远日，冷轮廓光来自船头后方；
   - 300 盏以上 HDR 自发光舷窗沿船体曲线排成 6–7 排，越靠船尾越短；约 8% 以各自 3–7s 周期缓慢明暗；
   - 船头一圈 accent 色的**全景舷窗带**（HDR，Bloom 拾取），引擎两团 accent 辉光 6s 呼吸，并真实照亮船尾；
   - 90s 一周期极慢漂移与约 0.5° 的微幅摆动。
4. **后期**：Bloom（阈值 1.1，只有光源发光）→ ACES 色调映射 → 4.5% 颗粒 → 暗角 0.32/0.55。
5. **镜头**：开场 2.5s 从远处推进（easeOutCubic），之后跟随鼠标做 ±0.35 单位的阻尼视差。
6. **前景内容列**：≥1024px 时内容（舰徽、眉标、标题、说明、登录卡、语言切换）左对齐在左侧 440px 一列内，左侧留白 96px，垂直居中，**与船不重叠**；窄屏时居中堆叠、船退到内容后方。登录卡是 `{components.brand-card}` 的全息面板版——`{colors.surface-1}` 90% 不透明，1px `{colors.accent-border}` 边，四角 8px 角标，极淡 accent 外晕；场景首帧后 400ms 淡入，卡片再晚 120ms 出现。
7. **文字**：64px 轨道舰徽 → 等宽眉标 `AXIOM · 操作系统` → 40px/600 标题「**AI 原生**的组织操作系统」（关键词 `{colors.accent-hover}`；英文可到三行）→ 一句说明「目标、任务、人与 Agent，在同一个系统里协同运转。」。**没有自检行，没有打字机效果，没有任何"花哨的提示语"。**
8. 语言切换在卡片下方，等宽 11px。

### 交互（画面必须是活的）
原则：输入只改变目标值，所有运动仍经过阻尼插值；不劫持键盘，不在输入框附近制造干扰；`prefers-reduced-motion` 时每个效果直接落到终态。

- **光标注视**：船体随光标偏航 ±3°、俯仰 ±1.5°（λ 1.5）；光标附近 0.7 单位内的舷窗最多亮 55%；前景星尘被光标轻轻推开（半径 1.4）。
- **拖拽环绕**：在内容列之外按住拖动，方位角 ±20°、俯仰 ±8°，松手后弹回（λ 2.5）；光标为抓手。滚轮在场景区域内推拉镜头（z 11–14），3 秒无操作后回位；页面本身不滚动。
- **表单注视**：聚焦邮箱框时镜头向船头推进 0.8 单位（约 1.2 秒）；聚焦密码框时舷窗调暗 20%、舰桥窗带提亮 35%，像船在"听"；失焦复原。
- **按键信号**：表单内每次按键（限流 ≤ 3 次/秒）让舰桥附近 3–5 盏舷窗脉冲 +40%、桅顶信标闪一次、窗带 +15%，400ms 内衰减。
- **登舰**（登录成功，共 2.6 秒，只在场景在跑且未开启减少动效时）：
  1. 确认 0–0.35s：引擎点火（辉光 ×2.6、点光 ×4），全船舷窗涌亮 +60% 后回落，舰桥窗带两次 60ms 应答闪光，导航灯沿舷窗排从船尾跑向船头指引入口，登录卡 300ms 淡出下沉，镜头微微后拉做预备。
  2. 掠航 0.35–1.7s：镜头沿船体坐标系中的 Catmull-Rom 样条飞行：从当前机位下潜、掠过近翼与引擎辉光、贴着船侧（约 0.5 单位）让舷窗成排流过、抬升绕到船头正前方 2.2 单位；速度曲线两端平滑、中段全速；视场 32→52 再落到 40，穿越时 ±2° 横滚；星点放大、星尘与 400 条速度线随速度拉伸，Bloom 随速度增强。
  3. 入口 1.7–2.35s：正对全景窗直入到 0.28 单位，窗带 ×3、舷窗 +60%，Bloom 升到 3.3，暗角退去，暖色光束与横向光晕从窗心展开。
  4. 登舰 2.35–2.6s：暖白遮罩 250ms 充满；进入应用后遮罩 600ms 退去，应用内容从 1.03 缩放、0 不透明度落定。
  过场期间忽略一切输入；失败时冷红告警加镜头后坐 0.3；减少动效或无 WebGL 时立即进入。
- **空闲巡航**：12 秒无输入后镜头进入约 2 分钟一周期的纪录片式慢巡航，任何输入即缓慢退出。
- **登录卡倾斜**：光标在卡片外围时卡片随之倾斜 ≤ 4°（λ 6）；光标进入卡片或卡片内有焦点时倾斜归零并保持静止（密码管理器的弹窗锚定在输入框上，几何一直变会闪烁），只有 accent 8% 的高光继续跟随；仅在 `(hover: hover) and (pointer: fine)` 下启用。
- **尺度参照**：2–3 架小型穿梭机每 20–40 秒沿曲线驶向船头；远处右下角一颗背光行星只露出带大气边缘的一角，亮度不超过船体四分之一。

### 加载期

### 降级与护栏
- 无 WebGL 2、软件渲染、`prefers-reduced-motion`：Canvas2D 静态星空 + SVG 母舰静帧，灯常亮；加载期间显示同一静帧。

## 舰内系统 v3（应用内的科技感）

登录是"登舰"，那么应用内就是**舰内**：《机器人总动员》里 Axiom 的内部——洁白光滑的表面、深色的舷窗与全息屏、处处是安静的仪表读数。原则不变：Linear 的克制与效率是底，科幻是一层薄薄的、有信息量的仪表皮肤；每个装饰都必须承载真实数据或真实状态，纯装饰一律不加。

**空间铁律**：应用内的每一块空间都先给有效信息。科技感通过页面风格（表面、分隔线、等宽读数）、交互元素（指令面板、状态 LED、悬停角标）、背景（点阵、状态栏星海）与动效（材质化进场、数字滚动、仪表扫动）来体现，不通过占位的装饰画面。登录页之外不再出现母舰模型。

**用词铁律**：科幻只是视觉主题，不是组织系统的组织方式。界面上的一切文字（标题、标签、提示、命令名、图片替代文字，中英文皆然）只用 `CONTEXT.md` 的词：组织概况、状态栏、快速命令、登录。**禁止**在任何用户可见的地方出现舰船隐喻（舰况、舷窗、引擎、信标、指令台、登舰、舰桥、母舰，英文的 bridge / ship / command deck 同理）。视觉元素可以用数据驱动（亮着的舷窗数量对应进行中任务），但不解释、不命名这种映射。隐喻词只允许出现在本规范和代码注释里。深色与浅色两个主题都要成立：深色是"夜航舰桥"，浅色是"Axiom 白色舱室"（白色表面、极淡冷蓝的分隔线、深色的舷窗带与屏幕形成对比）。

### 1. 舷窗带（状态栏）
状态栏是舰桥的舷窗：32px 高，背后一条 Canvas2D 星海缓慢流过（两层视差、软圆星点、密度与登录页星场一致，浅色主题下也是深色带，像白色舱室里的一条舷窗），前景是等宽读数。读数是活的：`AGENT 可用 n/m` 旁有雷达式脉冲（有可用的 Agent 时）；`今日成本` 带 24 小时迷你折线；数值变化时数字滚动。刷新周期 30s，标签页隐藏时停。

### 2. 组织概况（首页与运营看板顶部）
一块约 130px 高的纯读数面板：进行中 / 待验收 / 逾期 / 今日成本，26px 等宽数字，各带 24 小时趋势线，一行四列。**不放任何装饰性画面**——母舰模型只属于登录页；应用内的科技感来自页面风格、状态栏、背景、动效与交互元素，绝不占用本应显示有效信息的空间。

### 3. 仪表级数据
- 金额与 token 计数用滚动数字（odometer，每位 160ms `--ease-out`，仅在数值变化时滚）。
- 进度用带刻度的弧形仪表（arc gauge）：目标进度、验收通过率；圆环外圈 24 格刻度，已完成格点亮。
- 统计卡右上角迷你折线（sparkline，24 点，hairline-strong 描边，尾端一个发光点）。
- 吞吐柱状图的柱子带 accent 边光；今日柱呼吸。
- 动态流是**舰桥日志**：等宽时间戳列（`15:55:29`）、执行者芯片、事件类型用 LED 色点；顶部一行 `实时 · 最近同步 12s 前`，有新事件时 LED 闪一次并把新行 200ms 淡入。

### 4. 指令台（⌘K / Ctrl+K）
全局命令面板：等宽提示符 `›`，模糊搜索页面、任务、目标、Agent；动作：新建任务、领取任务、切换主题、切换语言、打开快捷键；上下键选择、回车执行、Esc 关闭；进场 120ms 从 0.98 缩放淡入，结果分组带眉标。触发按钮放在侧栏底部「快捷键」旁，显示 `⌘K`。

### 5. 面板与表面
- 主面板顶部一条 1px 的边缘高光（深色）/ 极淡冷蓝分隔（浅色）；面板 hover 时四角 6px 角标 120ms 浮现（只在一级面板）。
- 状态 LED：`进行中` 呼吸（3s），`逾期` 快两下再停 4s，`等待中` 常亮暗色。
- 路由切换：整页 100ms 只动透明度的极轻进场，无位移、无交错；键盘切页同样适用（轻到不会被感知为等待）。这是 2026-09-04 与用户确认的折中：高频操作原则上零动画，导航是唯一例外。
- 浅色主题：表面 #ffffff / #f7f8fa / #eef0f4，分隔线 `color-mix(accent 10%, #e3e6ee)`，文字 ink 不变；舷窗带与指令台保持深色。

### 6. Agent 页
Agent 头像是视窗双点 + 外环（§7 的状态语言，`AgentVisor`）：可用 = 双点常亮、环 success 3s 呼吸；执行中 = 双点交替、环 accent 常亮；等待输入 = 双点偏暖、环静止；已停用 = 双点 25%、环灰静止；开始干活时外环充满 520ms，停用 400ms 变灰。每行下方一行等宽遥测：`今日 3 段 · ¥4.17`（「最近活动」跟着状态列走，不在这里重复）。

**状态列**（152px，定义见 CONTEXT.md「Agent 状态」）：一行「指示灯 + 状态名」，下面一行 caption「最近活动 3 小时前」。
指示灯：执行中 = accent 呼吸，可用 = success 常亮微光（`tone="online"`），已停用 = 暗灯。界面上不出现「在线 / 离线 / 心跳」——
通过 MCP 接入的 Agent 没活干时本来就不说话，说它「离线」会把正常状态说成故障。表上方的筹码是「N 全部 · N 可用 · N 执行中」
（真有已停用的才多一枚），点一下按状态筛这一类。

### 7. 签名图标与状态动效
完整提案（含每枚图标的 SVG 与每条动效的样稿）见 `docs/design/icons-and-motion.html`，2026-09-04 经用户确认全面落地。要点：

- **类比只用于推导**：《机器人总动员》里每台机器人有一条指令、船长握着舵。目标 = 靴中的芽（证据），任务 = 压实的方块，待领取 = 方块堆，Agent = 视窗双点，验收 = 扫描，待确认操作 = 舵轮，执行记录 = 进度环，用量 = 太阳能电池，Bug = 刷子与异物，发现于 = 痕迹，阻塞 = 链，逾期 = 时钟加告警灯，已取消 = 气闸，通知 = 信标，参与角色 / 交接 = 双星环绕，甘特图 = 航线，动态 = 磁带，组织 = 客轮剪影（只做默认头像）。界面文字仍只用 CONTEXT.md 的词。
- **规格**：24 网格、1.5px 描边、圆角端点、单色随文字色；只有这 20 枚承载类比，其余图标保持通用。
- **状态动效只在状态真正变化时发生**（≤240ms，环境动效除外）：任务完成压实 420ms 并亮绿灯；目标完成发芽 480ms；进入待验收扫描 320ms；领取任务取走一块 260ms；Agent 开始干活充电 520ms，执行中双点交替，停用 400ms 变灰；批准待确认操作转舵 240ms；新通知信标闪两下；逾期双闪后休息 4 秒；交接双星环绕 12 秒；阻塞解除断链 200ms；成本数字滚动。
- **Agent 状态语言**（三个状态见 CONTEXT.md「Agent 状态」）：可用 = 双点常亮、环 3 秒呼吸；执行中 = 双点交替、环常亮；等待输入 = 双点常亮偏暖、环静止；已停用 = 双点 25%、环灰静止。不画脸、不做表情。

### 8. 甘特图 v2：宏观到微观
甘特图信息密度最高，规则是**把空间全给图**、**任何粒度都能看**、**能收能放**、**能全屏**。

- **空间**：页面标题与说明在图上方只占一行（说明折进「?」提示）；图区高度 = 视口剩余高度（不随行数无限增长，内部滚动，表头与左列固定）；左侧标签列可拖拽调宽（200–420px）并可收成 56px 的窄列（只留状态点与头像）；行高有「紧凑 28px / 舒适 36px」两档；图例收进底部一行，可折叠。
- **粒度**：刻度六档——时 / 日 / 周 / 月 / 季 / 年。表头始终两层（上层大单位、下层小单位，例如 月 + 日、季 + 周、年 + 月）。「时」档显示执行记录段（执行记录在任务条内按实际起止画成细段，Agent 与人不同色）；「季 / 年」档任务收敛为目标汇总条 + 密度热度（每格按任务数着色）。缩放：按钮、Ctrl/⌘ + 滚轮、触控板捏合，围绕光标位置缩放；「适应全部」一键把整个范围放进视口；切档 200ms 模糊过渡（已有）。今天线在所有档位可见。
- **收起 / 展开**：分组行（目标 / 团队 / 执行者 / 任务类型）左侧有折叠箭头；收起后该组显示一条汇总条（时间跨度、完成比例、任务数与逾期数）；工具栏有「全部收起 / 全部展开」；「未排期」默认收起并显示数量；折叠状态按分组方式记在 localStorage。
- **全屏**：工具栏「全屏」按钮（快捷键 F）：优先调用浏览器全屏 API 让图区独占屏幕；不可用时退到应用内全屏（隐藏侧栏与状态栏，图区铺满）。Esc 或再按一次退出；全屏内工具栏保留。
- **动效**：折叠展开 200ms / 150ms（高度过渡，沿用目标树），缩放围绕光标平滑，其余不变。

### 9. 目标与任务的区分
判定规则见 `CONTEXT.md`。界面上两者用**不同的视觉语言**，让人一眼知道自己面对的是"要做的事"还是"要达成的结果"，同时各自把必要信息给足。

| | 目标（意图） | 任务（要做的事） |
|---|---|---|
| 图标 | 靴中的芽 | 压实的方块 |
| 进展 | 64px 弧形仪表（下面汇总出来的百分比） | 状态徽标（它在自己流程里走到哪一步），**不显示百分比** |
| 版式 | 树形行，缩进 20px/层带引导线，根目标标题 16px/500，行高松 | 表格行，等宽日期与成本，行高紧 |
| 人 | 负责人（只能是人） | 任务负责人（人或 Agent，头像区分） |
| 必给的信息 | 任务完成数 / 总数、**状态摘要句**、计划区间、预算与已花 | 类型、状态、负责人、计划、优先级、成本 |
| 动作动词 | 规划类：新建子目标、新建任务、放弃 | 执行类：领取、开始、提交、验收 |

**状态摘要句**是目标行的关键：它直接说出下一步该干什么，按优先级取第一条命中的——
1. 还没有任务 → 「还没有任务，先拆几个任务出来」
2. 有逾期 → 「n 个任务逾期」（danger 色）
3. 有待验收 → 「n 个任务等验收」（warning 色）
4. 全部完成但未确认达成 → 「任务都完成了，确认达成吗？」并在行内给出「确认达成」按钮
5. 有进行中 → 「n 个进行中，n 个未开始」
6. 其余 → 「n 个任务未开始」

### 10. 页面整合：七个入口，同一批数据
十三个并列入口里有五个是同一批任务的不同看法，两个是重叠的分析页，两个是管理页。整合为**七个入口**（§12 再把待确认操作并入「我的工作」，最终六个），任何角色都从同样的七个入口进去，差别只在默认打开的页签与范围（ADR 0015 的预设决定）。

| 入口 | 内容 | 页签 |
|---|---|---|
| 首页 | 工作台（按角色的区块） | — |
| 组织概览 | 经营与运行数据 | 概览 · 成本 · 效率 · Agent（原「运营总览」四块并入） |
| 我的日程 | 时间 | 日 / 周 / 月三档，我的 / 团队（ADR 0032，§27） |
| 目标 | 意图 | 路线图 · 树（目标详情内嵌该目标子树的任务视图） |
| 任务 | 要做的事 | 列表 · 看板 · 甘特图 · 迭代 · 待领取 |
| 待确认操作 | 个人队列 | — |
| Agent | 登记与状态 | — |
| 组织设置 | 管理 | 基本信息 · 可见范围 · 工作台 · 成员 · 邀请 · 角色 · 团队 · 能力标签 · 价格表 · **流程**（原「流程」页并入） |

规则：
- **一条筛选栏管全部任务页签**：目标 / 团队 / 负责人 / 类型 / 迭代 / 状态类型，加范围选择器；切页签不丢筛选，筛选写进 URL 查询串，可分享。列表、看板、甘特图读同一份任务，切页签 200ms 交叉淡入（沿用甘特图切刻度的过渡）。
- **默认页签由角色决定，个人记住上次**：执行视角与小组视角的人进「任务」默认到看板，其余默认到列表；用户切过一次后按人记住（localStorage），不再按角色。组织概览默认「概览」页签。
- **旧地址保留**：`/board` `/gantt` `/backlog` `/sprints` 跳到 `/tasks?view=…`，`/dashboard` 跳到 `/overview?tab=cost`，`/task-types` 跳到 `/settings?tab=workflows`；迭代详情 `/sprints/[id]` 与任务、目标详情不变。
- **待领取**是任务页的一个页签而不是入口：它回答"我能接什么"，天然属于任务。
- 命令面板与工作台区块的链接跟着新地址走；侧栏七项，收起时七个图标。
- **页签条组件**（`ui.tsx` `Tabs` / `.htab`）：32px 高、13px 字，选中 = ink + 底部 2px accent 线，hover 只变字色与底色，整条下面一道 hairline；左右方向键切换。三个入口（任务、组织概览、目标）用同一个组件、同一套 `?view=` / `?tab=` 约定，内容区切换用 `fadeRepaint`（甘特图切刻度的那条 200ms 过渡）。
- **甘特图的框可复用**（`gantt/GanttFrame.tsx` + `useGanttScale` + `useGanttShell` + `GanttControls` + `Floating`）：刻度、两层表头、今天线、缩放锚点、适应全部、全屏与"行是什么"分开；任务甘特图（§8）与路线图时间线（§25）各自只注入自己的行。

### 11. 里程碑（ADR 0016）
目标页只有两个页签：**路线图**（默认，§25）与**树**，`?view=roadmap|tree`，同一批目标、同一个范围与筛选。原来的第三个页签「甘特图」画的是同一批行（目标、嵌套子目标、条上的菱形、拖两端改计划起止），已整个并进路线图（ADR 0022 补记）：`?view=gantt` 与记住的 `gantt` 都落到路线图，地址栏随即改写成 `?view=roadmap`。

**名字的规矩**：路线图按用途取名，画的是目标、最细到周；「任务 · 甘特图」保留原名，因为它画的是另一个对象——任务，按天的刻度，有依赖与执行记录。

- **里程碑 = 菱形**：画在所属目标的行上、对应日期处，8px；未到为 hairline 描边空心，已达到为 success 实心，逾期为 danger 实心并带小三角。悬停给出名称、日期、状态与"可以确认了"的提示。任务永远是横条，里程碑永远是菱形，两者不混用。它也是路线图上唯一出现具体某一天的地方：里程碑的日期是承诺，条的起止不是。
- **在哪儿画**：路线图的每一行（`roadmap/RoadmapRow`，密集时同一周内的合并成一枚）、任务甘特图按目标分组时的目标汇总行（规则相同）、以及目标详情的「里程碑」面板。三处共用 `gantt/MilestoneMarks` 这一个渲染器。
- **在路线图上怎么改**（并进来的那一套，交互细节见 §25）：拖菱形改日期；点菱形出小气泡（确认已达到 / 撤销 / 编辑 / 删除，`roadmap/MilestonePopover`）；在行的空白处双击就地新建，名称回车保存、Esc 取消，日期取双击那一格。改不动这个目标的人拖不动也建不了，气泡里只剩内容。所有改动乐观更新，失败回滚并用后端的整句理由提示。
- **目标详情**的「里程碑」面板：按日期列出，每条带状态、说明、「确认已达到 / 撤销」，末尾一行内联新增；目标行的状态摘要句在有逾期里程碑时优先提示「里程碑「X」已逾期」。
- 空状态：没有里程碑时路线图行上不画任何东西，面板里一句「还没有里程碑，双击路线图或在这里添加」。

### 12. 我的工作 = 待我处理 + 工作台
「首页」改名**「我的工作」**，定位：进入系统后看到的、需要自己操作干预或被通知的事项。六个入口：我的工作、组织概览、目标、任务、Agent、组织设置。

- **待我处理**（固定区，不能隐藏或挪走）：一行读数「待我处理 n」加六组事项，只看本人、不受范围影响，每条右侧是它的动作：等我确认的待确认操作（确认 / 拒绝）、等我验收的任务（去验收）、我负责但逾期的任务（打开）、指派给我但没开始的任务（开始）、等我答复的提问（答复）、未读通知（标为已读，进入页面停留 3 秒后自动标已读）。空组不显示；全空时一句「没有等你处理的事」和一枚安静的空状态。按紧急度排组：逾期 → 待确认 → 待验收 → 待答复 → 未开始 → 通知。
- **角标**：侧栏「我的工作」与状态栏读数用同一个 n（六组之和，通知只算未读）；原「待确认 n」读数并入。
- **工作台**：下面沿用 ADR 0015 的区块与预设；`proposals` 区块从目录中移除（已被待我处理覆盖），已有布局里出现它时忽略。
- **子页**：`/proposals/` 保留，作为待确认操作的历史记录（已确认 / 已拒绝 / 已过期），从「待我处理」里「查看历史」进入，不在导航里。
- 动效：处理完一条，行 200ms 淡出并收拢高度（沿用目标树折叠曲线）；读数用数字滚动。

### 13. 工作台的自由布局
「我的工作」整页是一张 **12 栏网格**（「待我处理」与「组织概况」也是区块，默认在最上面）（行高单位 120px，间距 16px）。每个区块有坐标与尺寸 `{x, y, w, h}`：宽 `min_w`…12 栏任意整数，高 1…6 行任意整数。窄于 1024px 时单栏、按 y 排序。

**编辑模式**（页头「编辑布局」进入，顶部固定「保存 / 取消 / 恢复角色默认」）：
- **拖动位置**：按住区块任意位置（表格、图表上也可以，编辑态下区块内容不响应点击）拖到新位置，按网格吸附；被压到的区块自动让位并向上压实，不留空洞。
- **拖动边框改大小**：右边缘、下边缘、右下角是把手（悬停时显现 2px 高亮），拖动按栏 / 行吸附；到 `min_w` 时停住并在边缘闪一下提示。
- **移除**：区块右上角的 ×；**添加**：末尾的「添加区块」瓦片打开目录，点一下放到最下方空位。
- 没有分段按钮、没有上下箭头；键盘可用：区块聚焦后方向键移动一格，Shift + 方向键改一格大小，Delete 移除。
- 改动在保存前只在本地；保存写回 `{key,x,y,w,h}`。

**尺寸适配**仍是每个区块自己的责任：宽 ≤ 4 栏为紧凑态（关键数字 + 前三条），高 1 行只显示头部读数；区块目录声明 `min_w`。组织设置的「工作台」页签用同一个编辑器给角色配布局。词汇仍用「区块」。

### 14. Agent 页的可见范围与「IM 集成」设置
- **Agent 页**：非管理员只看到自己的 Agent 与公共 Agent；公共 Agent 对非所有者只读（行上没有编辑 / 吊销 / 换令牌，带一枚「公共」标签与提示「由组织负责人管理」）。管理员看到全部，每行显示所有者。页头说明句按身份切换：「这里是你自己的 Agent 与组织的公共 Agent。」/「组织内全部 Agent。」
- **组织设置 → IM 集成**（需要「组织设置」权限）：
  1. 提供方卡片：目前只有飞书；未配置时一段说明（要在飞书开放平台建企业自建应用、开通通讯录只读权限）与「开始配置」。
  2. 凭据表单：App ID、App Secret（密码框；已配置时显示「已设置」并只允许重设）、同步根部门（可空 = 整个企业）、同步进来的人默认角色（下拉）、同步频率（手动 / 每小时 / 每天）、出网代理（私有化部署用，可空）。「测试连接」按钮就地显示结果句。
  3. 「预览同步」：不落库地列出将要新建 / 更新 / 保持的团队，以及新增、已有、将停用的成员数量，将停用的成员逐个列出（这是最危险的一步，必须先看到）。
  4. 「立即同步」：确认框写明会发生什么，执行后显示本次结果（新增 / 更新 / 停用数量与错误列表）；历次记录在下方按时间倒序。
  5. 同步进来的团队与成员在团队页、成员页带「来自{提供方名}」标签（文字来自接口的 `source_title`，如「来自飞书」「来自企业微信」）且名称不可改；待激活的成员显示「待激活」状态与「复制邀请链接」。
- 所有句子完整、直白；不出现 open_id、tenant 之类字段名。

### 禁止
仍然禁止：扫描线、粒子雨、打字机文案、霓虹描边、随机闪烁、超过 240ms 的界面动画、任何不承载数据的装饰。

## 交互与体验原则

沿用 v1 的十条：先扫后读（统计芯片条）、动作就近（行内悬停动作）、状态可解释（禁用必有原因）、不打断（抽屉）、反馈即时（Toast + 乐观更新）、加载有骨架、一致的时间语言、Agent 与人并列可辨、甘特图是重点页面、看板四面板。

再加两条（调研 Kaneo 之后，2026-09）：
- **动作先说后果**：不可逆或影响他人的动作（放弃 / 删除目标、停用成员、停用 / 合并团队、转让组织负责人、移除 Agent、撤回邀请、结束迭代、更换提供方、删除能力标签、恢复角色布局……）一律走 `ConsequenceDialog`：标题写对象，「这会」下面一句一条写清会发生什么，能数的必须带数字（「名下 3 个未结束任务需要重新指派」「下面的 2 个子目标一起拿掉」），没有影响的那条不写，末尾一句"随时可以恢复"之类的补充。数字要现算就先显示「正在统计影响范围…」并禁用确认。按钮文字是动词本身（放弃、停用、移除），不是「确定」。
- **空状态写下一步**：每个空状态一句话说清"为什么空"和"接下来做什么"，并给一个动作按钮（「这个目标还没有任务，先拆几个出来」+「拆一个任务」；「没有等你处理的事」+「看待领取的任务」；「没有待领取的任务：所有任务都有人负责。要放一个出来给人领，把它的负责人清空」+「新建任务」）。筛选后为空与本来就空是两句不同的话，前者的动作是「清除筛选」。只有动态这类"做点什么才会有"的地方可以没有按钮，但仍要说清什么会出现在这里。

## 组件细则（沿用 v1 评审结论，颜色按本版）

- 统计芯片条：32px 高，`{colors.surface-1}` 底 + 细线，数字 14px/500，语义芯片前 6px 指示灯；选中 `{colors.accent-border}` 边 + `{colors.accent-bg}` 底；第一枚永远是「全部」。
- 头像：中文名取最后一个字，拉丁名取首字母；Agent 方形机器人图标；20 / 24 / 32px 三档。
- ID 只出现在详情页面包屑和侧栏「ID」行（等宽遥测色 + 复制）；列表不显示 ID；行高 40–44px；单元格不超过两行。
- 表格：非文本列固定宽度；行内动作固定在最后一列，悬停出现，不抖动。
- 动作条：只有向前推进的步骤用主按钮；阻塞 / 解除 / 提问用次级；取消 / 打回 / 测试不通过 / 不修复用危险；三组之间细线；禁用步骤置灰并在气泡里解释；指派 / 附上交付物 / 写评论为右侧第三级按钮。
- 动态：默认 10 条 + 「查看全部 (N)」；本任务页不重复任务名后缀；同一人 5 分钟内的连续动作合并。
- 目标树：每层缩进 20px + 引导线；有子项的行有折叠箭头；行内含负责人、三个带标签的小指标、进度条与百分比、超预算标签；悬停动作查看 / 新建子目标 / 新建任务。
- 抽屉表单：按「基本 / 安排 / 人员」分组；短字段两列；日期控件与输入框一致。
- Agent 列表：「N 项授权」折叠 + 气泡；能力标签最多 3 个；状态灯 + 执行中/可用/已停用，下面一行「最近活动 …」；「最多同时 N 个」。
- 成员列表：只在停用时显示状态标签。
- 拖动排序的把手（`.gt-grip`）：压在行左内边距里的六点，平时 `opacity: 0`，行悬停或行内有焦点时才浮现；`cursor: grab` / 按住 `grabbing`。它是 `role="button" tabindex="0"` 的一格，键盘上下键等价于拖一格——排序不能只有鼠标一条路。
- 就地下拉（`InlineSelect`）放进表格时必须开 `portal`：表格的滚动壳（`.tbl-wrap` 的 `overflow-x`）会把绝对定位的菜单剪掉，`portal` 让它像 `Menu` 一样挂到 body 上、固定定位。
- 让人挑颜色的地方（目标类型的色点）只给语义色那一组的取值，按名字挑（薰衣草蓝 / 绿 / 琥珀黄 / 红 / 灰），不给自由填色号——色号一旦自由，画面里就会长出第二个强调色。
- 看板：短日期坐标轴、隔一显示、柱子悬停数值；大数字 24px/600 + 12px 说明基线对齐。
- 小指标面板：数字 20px/500 + 说明，不带面板头。
- 品牌页：徽标与字标同一行；标题最多两行；卡片 400px。

## 禁止

- 第二个强调色、渐变、玻璃拟态、投影、霓虹描边、扫描线动画、粒子爆炸、赛博朋克式的青色 + 品红。
- 硬编码任何颜色（组件里只能出现 token：Tailwind 的 `bg-surface-1` 之类，或 `var(--c-*)`）；在品牌页提供浅色。**唯一的例外**是存进数据库、由用户挑的颜色（目标类型的色点）：它要跨语言、跨主题、跨端稳定，只能存具体色号——那份可选清单必须与语义色一一对应，写在一处（`GoalTypesTab` 的 `COLORS`），不许各处再写一遍。
- 粗于 600 的字重；正文与按钮粗于 500。
- 用图标代替文字按钮；emoji。


**接入向导**（ADR 0017 补记二）：IM 集成页签是一条从上到下的路，不是一张表单。步骤条：① 选平台 → ② 填凭据 → ③ 权限检查 → ④ 同步范围 → ⑤ 预览并同步 → ⑥ 定时。每一步只露出当下要做的事，做完的步骤折成一行摘要（可点开改）。② 保存即测试，成功后自动进 ③。③ 是一张检查清单，每项一行：状态点（绿 ✓ / 黄 待处理 / 红 阻塞）、标题、一句"怎么做"、「打开{平台}控制台」链接（直达该应用的那一页），底部一个「我已处理，重新检查」；全部绿了才自动进 ④。④ 根据检查结果给选项：权限范围是全员时默认"整个企业"，否则列出被授权的部门让人勾选作为同步根。⑤ 预览表格和现有一样，通过后才出现「立即同步」。⑥ 频率与代理。已接入后页面顶部仍显示 ③ 的即时状态摘要（「6 项检查全部通过 · 上次同步 …」），有坏的就展开。文案里只说"去哪儿点什么"，不出现权限的英文代号；代号只在「详情」里给。

**冲突与对应关系**（ADR 0017 补记四）：预览表格上方多一组「需要你确认」：每条一行，左边 IM 里的对象（名字、部门、邮箱/手机尾号），中间"可能是"，右边系统里的疑似对象（名字、团队、来源），最右三个动作「合并到已有」「作为新建」「跳过」；有多个候选时右边是下拉。认法用一句小字说明（「邮箱相同」「姓名相同且都在研发组下」「团队同名同层级」）。全部处理完之前「立即同步」显示为「还有 N 条要先确认」并禁用。状态视图里常驻「预览同步」按钮和「对应关系」面板（三个页签：已绑定 / 可能重复 / 已跳过；已绑定可「解绑」，可能重复可「合并」，已跳过可「重新考虑」），所以同步完之后仍能回来处理。成员页表格里疑似重复的人名旁有一个小提示点「可能与 X 重复」，点开即合并对话框。团队合并对话框要写清"旧团队的成员、目标、任务、迭代会并过去，旧团队停用"。

**提供方是数据，不是分支**（ADR 0017 补记）：IM 集成页签先让人选提供方（飞书、企业微信…），卡片列表来自 `GET /org/directory/providers`。凭据表单、前置条件、根部门默认值都按提供方的声明渲染：保密字段是密码框（已设置时显示「已设置 ••••」和「重设」），非保密字段是普通输入框。前端代码里不允许出现 `if provider === "feishu"`；新增平台时前端零改动。已接入后切换提供方要二次确认，说明旧来源的对应关系会变成手工维护。

### 15. 就地编辑（任务与目标详情）
详情页不是只读的报告，而是对象本身。能改的地方就在原位改，不跳表单、不弹整页对话框。

- **标题**：悬停出现淡淡的底色与铅笔图标，点击变成同字号的输入框；回车保存、Esc 取消、失焦保存。空标题不保存并回到原文。
- **描述**：点击进入多行编辑（自动增高），底部出现「保存 / 取消」两个小按钮；⌘/Ctrl+Enter 保存。
- **基本信息表**（负责人、验收人、优先级、计划开始/结束、预估工时、工作量、迭代、归属目标、上级、团队、预算、截止日、仅限人工、参与角色、所需能力、自定义字段）：每一行的值本身就是控件——下拉、日期、数字、开关、选人。改完即保存，一行一个请求，右侧短暂出现一个 12px 的对勾（`--motion-fast`），失败则值回退并在行下用一句中文说明原因。
- **所有改动都有动态**：保存成功后动态面板实时出现「某人把标题从「A」改成了「B」」这类句子（后端产生，前端不拼）。
- **权限**：不能改的人看到的就是普通文本，没有悬停底色、没有铅笔；不用灰色禁用控件占位。Agent 不能改的字段（验收人、优先级、归属目标、迭代、参与角色、仅限人工）对人照常可改。
- **已结束的任务 / 已达成的目标**：只允许改描述与备注类字段，其他行回到只读文本，标题旁说明「已结束，改不了计划」。
- 移动端（<768px）：同样的行，控件占满一行；标题编辑用同一套。

不做的事：批量改多个任务（用列表页的多选另行设计）、改任务类型（流程绑定在类型上，改类型等于换任务）。

### 16. 成员与团队（组织设置）
参照成熟 IM 管理后台的组织架构页：**左边是团队树，右边是选中团队的成员表**。原来的「成员」「团队」「邀请」三个页签合并为一个「成员与团队」页签。

- **左栏（团队树）**：顶部搜索框（按姓名、邮箱找人，命中后右栏定位到那个人所在团队并高亮）；树以组织名为根节点，每个团队一行：图标、名称、人数；共享边界的团队带一个小标记；来自 IM 同步的团队带「来自{IM 名}」提示且不能重命名。每行右侧 ⋮ 菜单：新建下级团队、编辑…（名称、上级、团队负责人、共享边界一次改好；同步来的名称锁住）、重命名、移动到…、设为 / 取消共享边界，最后是危险项——同步来的团队只有「停用」（下次同步还会对上），手工建的只有「删除」——有成员、有下级也能删，但先弹后果对话框：**下级团队一起删**，算出几人离开（几人从此没有团队）、几个下级跟着删（点名）、几个目标与迭代不再归口、边界标记一起去掉；不空的团队还要照着输入团队名才能按删除（二次确认）。右栏标题旁显示团队负责人。底部固定「＋ 新建团队」。可折叠展开，记住展开状态。
- **右栏头部**：面包屑「组织设置 › 成员与团队 › {团队}」；团队名 + 「总人数 N」（含下级）；右上角「已停用成员」入口（进入只看停用的人的列表，可恢复）。
- **筛选与操作条**：筛选「状态：全部 / 正常 / 待激活 / 已停用」、开关「仅显示直属成员」（默认关，显示含下级）；操作：「批量变更团队」（选中若干人后可用）、「导入 / 导出」（CSV：姓名、邮箱、团队、角色；导入先预览再确认，和 IM 同步预览同一套形态）、「邀请成员」（邮箱 + 角色 → 生成邀请链接，进入列表为「待激活」）、「添加成员」（直接建账号）。
- **成员表**：多选框、姓名（头像 + 名字，待激活 / 已停用用状态标签）、账号状态、邮箱、角色（最多显示两个，其余 +N）、团队（直属团队，含下级时显示所在团队名）、来源（手工 / 来自{IM}）、操作（详情 · ⋯：变更团队、改角色、复制邀请链接、停用 / 恢复、转为组织负责人）。点姓名打开右侧抽屉编辑（同现有成员抽屉），来自 IM 的姓名只读。
- **状态**：树与表都支持空态（「这个团队还没有人」+ 邀请 / 添加两个动作）与加载骨架；批量操作有确认对话框，说明会影响多少人；所有改动即时反映在树上的人数。
- **窄屏（<1024px）**：树折叠成顶部的下拉选择器，表格保留。
- 词汇仍是「团队」「成员」「待激活」「已停用」，不用「部门」「离职」。

### 17. 执行简报（任务与目标详情）
任务详情不再按数据库字段排，而是按**执行者接到任务时需要知道的顺序**分四段，每段一行眉标（两位序号 + 标题 + 一句说明，`BriefSection`），眉标后一道细线：

| 段 | 任务详情 | 目标详情 |
|---|---|---|
| ① 现在要做什么 | 标题、状态与动作栏（吸顶）、描述与自定义字段、「这类任务的做法」（任务类型给执行者的说明，来自 `GET /tasks/{id}/brief`）、「走「提交」需要：结果摘要、交付物「PR」」、参与角色 | 目标是什么：说明紧跟页头、与下面的内容同宽（就地改，空着时显示一句邀请写的占位）、进度仪表、状态摘要句；动作在页头（确认达成 / 放弃 / 删除） |
| ② 为什么做 | 目标链（根目标 › … › 所属目标，每级可点，末级仍是就地编辑的下拉）、最近的里程碑、优先级、计划起止、迭代、上级任务 | 上级目标链、计划起止、截止日、里程碑面板 |
| ③ 前面发生了什么 | 前置任务的结果与交付物（brief 的 `predecessor_results`）、关联、交付物、评论、执行记录、动态 | 子目标、名下任务表、动态 |
| ④ 如何验收 | 验收人、验收条件（从流程推出：进入待验收 / 成功终态的步骤各要求什么、由谁走；加上 `result_schema` 要填的字段）、预计工时与工作量、成本与用量 | 负责人、团队、预算 / 已花 |

右栏只剩次要的「基本信息」：ID、负责人（仍是指派入口）、创建者、创建时间、类型与流程版本、状态类型、进度、实际起止、仅限人工、能力要求。所有就地编辑（§15）原样保留，只是换了位置。

**为什么是这个顺序**：执行者（尤其是 Agent）不该跨页面拼上下文——先知道要做什么和怎么做（①），再知道它服务于什么、有多急（②），然后看前面留下了什么可以接着用（③），最后知道做到什么程度算完（④）。今天的详情先看到的是 ID 和创建时间，这些对执行没有帮助，所以退到右栏。

**三级密度：卡片 → 抽屉 → 全页**。列表行与看板卡片点一下先开右侧抽屉（`TaskPeek`，480px）：只有 ① 与 ②（只读）、同一份动作栏（可领取 / 开始 / 走步骤 / 指派）、最近 5 条动态，底部「打开完整页」。行里的标题链接与卡片上的回车仍直接进完整页。抽屉打开时地址栏带 `?task=<id>`，可分享；Esc、关闭按钮都清掉参数。抽屉里改了任务（走步骤、指派）后当前页签重新取数。

### 18. 筛选芯片
任务页的一条筛选栏（§10）扩到九个条件：关键词、目标、团队、负责人、类型、迭代、状态类型、优先级、截止日（已逾期 / 今天到期 / 7 天内到期 / 没有截止日）。全部写在地址栏查询串（`?q=&goal=&team=&assignee=&type=&sprint=&state=&priority=&due=`），列表 / 看板 / 甘特图 / 迭代 / 待领取共用同一份，切页签不丢；接口不认的条件在前端过滤（优先级、截止日、关键词各页签都在前端；看板拿到卡片后过滤并重算列计数）。当前页签吃不下的条件禁用并在气泡里给理由，它的芯片变灰。

生效中的条件在控件下方显示为一排**芯片**（`.filter-chip`，24px，accent 底与边）：「状态类型 进行中 ×」，每枚右侧的 × 只去掉这一条，末尾「清除筛选」一键清空。用户随时看得见"我现在看的是什么"。关键词输入框在最左，`f` 或 `/` 聚焦，Esc 失焦。

### 19. 前缀式快捷键与快速命令
两键组合：按下前缀后 1.5 秒内等第二个键，右下角出现一枚小提示（`.chord-hint`：前缀 + "然后" + 能接的键与含义），按了别的键或超时即消失。输入框里、有对话框打开时都不触发。

| 组合 | 动作 |
|---|---|
| `t c` / `g c` | 新建任务 / 新建目标（在任务页 / 目标页直接开抽屉，否则跳过去带 `?new=1`） |
| `g t` / `g g` / `n o` | 去任务 / 去目标 / 打开「我的工作」 |
| `v l` `v b` `v g` `v s` `v k` | 任务页签：列表 / 看板 / 甘特图 / 迭代 / 待领取 |
| `j` / `k` | 任务列表与看板里上下选（行左侧 2px accent 线 / 卡片 accent 边） |
| `Enter` / `o` | 打开选中任务的抽屉 / 完整页 |
| `f` `/` | 聚焦筛选关键词 |
| `?` `[` `Esc` | 快捷键表 / 收起侧栏 / 关闭抽屉、取消选中 |

快速命令（⌘K）在原有页面、任务、目标、Agent 搜索之外增加：动作组里的新建目标、打开待我处理、编辑工作台布局（动作右侧标出对应的组合键）；「范围」组列出会话给的全部档位，当前那档带「当前」；「成员」组（只对有组织设置入口的人）按名字 / 邮箱找人，回车到成员与团队页并定位到那个人。快捷键表按跳转 / 新建 / 任务页签 / 列表与看板 / 通用五组排。

### 22. 待确认操作行要写清"确认的是什么"
待我处理与待确认操作页的每一行，在后端那句「确认后会……」下面，按动作把载荷里人最该看的几样摆出来（`ProposalDetails`）：推进任务的说明、交付物的标题与地址、评论正文、新建对象的标题与描述、改了哪些字段、目标方案的规模（并给「去逐条勾选」的入口），末尾一行是针对的对象（可点进去）。认不出的动作什么也不显示，不塞 JSON。Agent 页的「编辑」抽屉与注册抽屉是同一个：改名字、能力标签、授权、最多同时任务数，令牌不变；公共与否注册后不能改。

### 21. 授权预设（接入确认页与注册抽屉）

### 20. 任务序号与显示偏好
**序号**：每个任务有组织内递增的可读序号 `#123`（`number`），等宽小字（`.task-no`，12px，ink-subtle）印在标题前：任务列表（自己一列「序号」，也在标题链接里）、看板卡片、待领取行、甘特图行、抽屉标题、详情面包屑（点一下复制 `#123`）、待我处理行、动态里引用任务的那一句。`tsk_xxx` 只留在详情右栏的「ID」行。快速命令输入 `#123` / `123` 时第一项是「打开任务 #123」，回车走 `/task-by-number/123/`（找到后 replace 到 `/tasks/{id}/`，找不到显示后端那句「没有序号为 N 的任务。」）；任务页的关键词筛选也认序号（精确匹配）。

**显示偏好**（`GET/PUT/DELETE /me/preferences`，目录 `GET /me/preferences/catalog`）：一个人怎么看界面，五项——任务列表显示哪些列、看板卡片显示哪些字段、默认任务视图、紧凑模式、侧栏默认收起。解析与工作台同一套（ADR 0015）：**逐字段** 个人 → 角色 → 系统默认，后端解析好并带 `sources`。前端登录后拉一次存在模块级（`lib/preferences.ts`），生效点：
- 列：`TaskTable` 按 `task_list_columns` 出列（顺序固定按目录；「标题」固定有；工作台区块 / 迭代详情的紧凑用法仍会去掉验收人、迭代、优先级、工作量、成本）。
- 卡片：`Board` 按 `task_card_fields` 画序号、负责人、截止日、优先级、工作量、目标；类型与状态总在。
- 默认页签：地址栏 → 本人切过的那一次 → 偏好里明确设过的（`sources.default_task_view ≠ default`）→ 按角色推断（§10）。
- 紧凑：`body[data-density="compact"]`，表格行 6px、表 13px、页面上下留白 12px。
- 侧栏：偏好只是兜底（`setSidebarDefault`），这台浏览器上手动收起 / 展开过（localStorage）就听手动的。

页面：**个人设置**（`/me/`）是每个成员自己的页面，从侧栏页脚自己的名字（头像 + 姓名）点进去，不在组织设置里——组织设置只给管理员；旧地址 `/settings/?tab=me` 自动跳过来。没有组织设置入口的人，侧栏那个位置是只读的「流程」。页里第一块叫「我的偏好」，后面是通知、外部日历、代码平台身份。五行控件（`PreferenceForm`）：勾选列 / 字段、分段的默认视图、两个开关；每行右侧一枚来源标签（个人 / 来自角色「产品」/ 默认）；改一项立即保存（只发这一项），面板遥测位写「已保存」；「恢复默认」走后果对话框后 `DELETE`。角色默认在 组织设置 → 工作台 → **显示偏好** 面板：一行一个角色（成员数、设过的项），「编辑」打开同一份表单（来源标签写「角色」/「默认」），改一项即 `PUT /org/preferences/{role}`，「恢复默认」`DELETE`。

### 21. Agent 接入向导
「Agent」页的主按钮从「注册 Agent」改成**「接入 Agent」**（ADR 0018）；它左边再放一枚**「复制给 Agent 的链接」**（`CopyButton`，复制 `<来源>/connect`，成功弹一条「已复制。把它贴给你的 Agent 就行。」，ADR 0024）——不想开向导的人，一下就把链接拿走了。向导对话框三步（`ConnectWizard`，步骤条 `WizardSteps` 五格：选运行环境 › 贴链接给 Agent › 批准并授权 › 连接检查 › 试领一个任务）：
1. **选运行环境**：Claude Code / Cursor / OpenAI Codex / 其他 MCP 客户端，四张单选卡片各带一句"脚本会替你做什么"。
2. **贴链接给 Agent**（首选在上，ADR 0024）：`<来源>/connect?client=…`（`CopyLine`，带上刚选的运行环境，说明书就只给那一种客户端的写法）+ §26 那四句「接下来会发生什么」。下面隔一条细线是次选的**「或者在终端里自己执行」**：原来那一行 `curl -fsSL '<地址>/api/v1/agent-auth/connect.sh?client=…' | sh`，仍然说明令牌只进客户端配置、Windows 用 WSL。再下面是**「或者手工配置」**折叠项，原样保留（注册抽屉 → 一次性令牌）。三条路的顺序就是推荐程度。
3. **等待批准**：说明 Agent 或终端里的脚本会给出验证码和网址，附一段示例输出；输入框「输入终端里显示的验证码」→ `/agents/connect/?code=`。

**批准页** `/agents/connect/?code=ABCD-1234`（需登录；`GET /agent-auth/device/{code}`）：先列申请是什么（验证码、运行环境、申请时填的名字、申请时间、过期时间），表单：Agent 名称（留空用申请里的名字，再缺省用运行环境名）、能力标签、**每项授权三选一**（允许 / 需要确认 / 拒绝；默认执行 = 需要确认、评论 = 允许、其余拒绝；「管理流程」只有需要确认 / 拒绝）、最多同时任务数、是否公共（只有组织负责人看到）；「批准」/「拒绝接入」。批准后同页进入**连接检查**：每 3 秒 `GET /agents/{id}/check`，最多 2 分钟；LED + 一句人话（后端的 `hint`）+ 最近调用的工具；收到它的第一次请求后步骤条走到「试领一个任务」，给「去待领取任务」。已拒绝 / 已过期 / 找不到都是完整的句子加"该怎么办"，没有 `code` 时是一个输入框。

Agent 行多一列**运行环境**（`runtime` → Claude Code / Cursor / OpenAI Codex / 其他 MCP 客户端，列宽 112px，名字长了截断并带原名气泡），行内动作多一个**「检查连接」**：结果显示在遥测行下面（LED + hint + 最近工具），任何人都能对能看到的 Agent 点。多这一列一个按钮之后 1440 下行内挤了，所以：名字格的遥测行（今日 N 段 · 成本）一项一个不折行的小块、分隔点跟在后一项前面——窄了整块换行，行尾不会剩一个孤零零的「·」，也不会被挤成一列一个字；「授权」列的标签只写「7 项」（表头已经写了「授权」），把省下的宽度让给行内动作，四个动作在 1440 下都完整可见。

### 22. 通知外发（ADR 0019）
三层里的每一层各占一个地方，界面上不互相解释别人的事：

- **组织设置 → 通知**（`?tab=notifications`，要「组织设置」权限）：`GET/PUT /org/notifications`。
  - **一个通道一张卡**（飞书 / 企业微信 / 邮件 / Webhook，顺序按接口的 `channel_order`）：左边一颗状态点（能用 = 绿、连续失败 = 红、没接入 = 灰）、通道名、「已接入 / 未接入」标签、IM 通道多一枚「IM」标签；右边一个「允许外发」开关（改了立刻存）与「发送测试」。卡里依次是：不可用时的一句原因（接口的 `hint`，如「先在「IM 集成」里接入企业微信，这里才能用它发消息。」）、还没接入时的「接入前要准备」编号清单、按提供方声明渲染的凭据字段（**与 IM 集成同一套 `CredentialField`**：保密字段已设置时只显示「已设置 ••••」与「重设」，选填的在标题后标「选填」）、一行健康（「最近投递正常」/「还没通过这个通道发过」/「连续 N 次没发出去」+ 最后一次的原话 + 时间）。
  - **「发送测试」**给自己发一条，结果就地显示成一句话（成功绿底、失败红底），句子由后端给（「已通过飞书发给你，去看看。」/「这个成员没有绑定飞书身份，收不到飞书消息。」）。
  - **允许外发的事项**：一排勾选框（待确认操作、等我验收、指派给我、提问、任务被阻塞、逾期、里程碑到期），勾一下就存；说明句是「没勾的事项只留在站内「待我处理」里，不往外发。」
  - **最近投递**：时间 / 事项（标题 + 事件类型）/ 通道 / 收件人 / 状态 / 错误，右上角两个窄下拉按通道与状态筛。
- **个人设置 → 通知**（人人可进）：`GET/PUT/DELETE /me/notifications`。一张**小矩阵**——行是事项（只列组织允许的），列是组织开着的通道，格子是勾选框，改一格立刻存；一行一个都没勾时行首写「只站内」，行尾一列写来源（你设过 / 默认）。某个通道要绑 IM 身份而我没绑时，那一列不给勾（画「—」），并**在表下面用整句写清楚**「你还没有绑定飞书身份，收不到飞书消息；同步 IM 集成或让组织负责人在「对应关系」里绑定。」下面是**安静时段**（一个开关 + 两个时刻，关掉即 `null`）与面板右上角的「恢复默认」（后果对话框 → `DELETE`），再下面是「我的最近投递」（同一张表，不带收件人列）。
- 提供方是数据不是分支：通道名、字段、前置条件、提示句、不可用原因全部来自接口，`NotificationsTab.tsx` 里没有任何平台名。

### 23. 代码平台与外部链接（ADR 0020）
- **组织设置 → 代码平台**（`?tab=code`，要「组织设置」权限）：与「IM 集成」**同一条被引导的路**，公共零件抽在 `settings/wizard.tsx`（`StepRow` / `ProviderCards` / `CredentialField` / `ChecklistStep` / `CheckSummary`）。五步：① 选平台（GitHub / GitLab / Gitee 三张卡片，各带「接入前要准备」与一句「到哪儿去找令牌」+「打开{平台}控制台」）→ ② 填凭据（按声明渲染，选填的标「选填」；按钮是「保存并检查」）→ ③ 接入检查（凭据可用 / 能读到仓库 / 回调已建好，每项状态点 + 一句怎么做 + 「打开控制台」+「详情」，底部「我已处理，重新检查」）→ ④ 选仓库（现场读平台上的仓库，勾选即保存；系统去建回调，建不上的那一行带「回调没建上」与一句原因）→ ⑤ 完成（回调地址与回调密钥两行都能一键复制，下面一句说清要粘到平台的哪一页）。
- 当前在哪一步**从数据推**（没选平台 → ①；没配好 → ②；清单有阻塞 → ③；没选仓库 → ④；否则 ⑤），不记在状态里；做完的步骤折成一行摘要可点「修改」。接好之后顶部常驻一条状态摘要：平台名 · 「已接入」· 已接 N 个仓库 · 检查摘要 ·「重新检查」/「更换平台」（更换走后果对话框：链接留着、旧回调要自己去清、密钥重新生成）。下面一块「能触发流程的事件」把六种事件列成标签。
- **任务上的外部链接**：任务详情③段第一块「外部链接」。一行一条——类型标签、标题（点开去那边，带外链图标）、状态标签（打开 / 草稿 / 已合并 / 已关闭 / 通过 / 失败，颜色：打开与通过是强调 / 成功色，失败红，草稿与已关闭灰）、「由 {登录名}」、更新时间、能改的人行尾有「移除」（后果对话框说明「只是从这个任务上摘掉，代码平台上的东西不受影响」）。「挂上链接」是一个小对话框：类型下拉 + 地址 + 选填标题。
- **PR 小标**：任务列表行的标题格与看板卡片上是一枚 `PrChip`——`PR + 状态`，多条时右上角带 `+N`，点一下直接去代码平台。数据来自行上的 `pr` 字段（最近更新的那条 PR 链接），没有 PR 就不画。
- **流程页的触发标签**：一步声明了 `triggered_by` 时，步骤名下面多一枚小标签「PR 合并时自动走这一步」（只读；六种事件的界面名写在 i18n 的 `code.event.*`，流程页对每个成员只读可见，不为一枚标签去要「组织设置」权限）。
- **我的代码平台身份**：个人设置最后一块，一个登录名输入框 + 「绑定 / 解绑」；组织还没接平台时只有一句「接上之后，这里可以填你在那边的登录名。」

### 24. 详情右栏的验收小卡
任务详情右栏在「基本信息」**之前**多一张紧凑的「验收」卡：验收人、验收条件（只取第一条，两行截断，气泡里是全部）、工作量 + 预计工时、成本；条件多于一条时卡底一句「完整的验收条件在下面第 04 段」。动态长的时候不用一路滚到 ④ 才知道谁验收、按什么验收；④ 仍然是完整版，两处同源（都从流程推出来）。

### 25. 路线图（ADR 0022，取代 ADR 0021 的分列形态）
「目标」页的第一个也是默认的页签，与树并列：同一批目标的另一种看法。它回答的是"接下来要解决什么、为什么是它、大概什么时候"，读者包括不在系统里干活的人。原来的「目标 · 甘特图」页签已整个并进来（§11）：它画的是同一批行，只是没有粒度雾边、泳道与类型，重复的那一张图删掉了。**名字按用途取**：路线图画目标、最细到周；「任务 · 甘特图」画任务、按天、有依赖，名字照旧。

**它是一张粗刻度的时间线，不是卡片板。** 上一版的三列（现在 / 下一步 / 以后）卡片已经删掉，不留作第二排布：目标身上本来就有计划起止与里程碑日期，三列把它们压没了，父子目标还被拆进不同列。改成时间线之后，"不承诺某一天"交给**刻度**和**时间粒度**保证，而不是交给"什么都不画"——全行业没有一家靠取消时间轴解决这件事，他们靠的是降刻度。

- **横轴只有四档**：周 / 月 / **季度（默认）** / 年，**最细到周**，不开天与小时（那是甘特图的事）。滚轮连续缩放也被夹在这四档的范围内。刻度与分组记住上次选择。保留今天线（1px 强调色竖线 + 表头三角）。
- **一行一个目标**，行高 44px；子目标缩进 16px 一级、可折叠（折叠状态记在本地），折叠后父行画跨整棵子树的汇总条。泳道头 32px。**路线图上不画任何任务**。
- **左侧信息列 320px**（窄屏 200px），不随横轴滚动，一行四段：① 折叠箭头 + **目标类型芯片**（打头：类型色点 + 名字，18px 高的浅底小胶囊，最宽 96px，读作"这是一个产品目标：……"；标题先截断，芯片不缩——类型单独占一行会和折叠箭头错位）+ 信心度圆点（高 = 成功色、中 = 中性、低 = 警示色，没填是一圈空心）+ 目标标题（截断，悬停出全名）+ 「从子目标推出来的」那枚箭头；② 上级目标（只在「还没排期」里）与成果指标，单行截断、淡一级，**左边让开信心度圆点、与标题文字对齐**，都没有就不占行；③ 负责人头像与名字；④ 细进度条 + 百分比。**"一眼读出进度与信心"靠这一列，不靠条。** 行尾是**悬停出现的快捷操作**：「＋」在这一行下面内联新建子目标（缩进一级、一个标题输入框加一枚「加说明」，点开后行长高、下面多一个三行的说明框；回车创建、⌘/Ctrl+Enter 也创建、Esc 取消；继承上级的团队与类型、负责人是自己；创建后选中新行），「⋯」菜单里有新建子目标、复制目标（同一上级下建一份「（副本）」，字段照抄）、打开详情、看任务甘特图。改不动的人也看得到菜单，但新建与复制按不了，原因写在菜单项下面（§「禁用必有原因」）。在时间线上补一个子目标应当像在清单里补一行，不弹抽屉。
- **条有四种画法，把"这个日期有多硬"画出来**（高 18px、圆角 4px、按汇总进度填充）：
  1. **到周** —— 硬边实条，两端已吸到周一与周日；
  2. **到月 / 季度 / 半年 / 年** —— 两端吸到刻度边界，各做一格宽的渐隐雾边（SVG `mask` + 两条 objectBoundingBox 的渐变，`rm-fade-l` / `rm-fade-r`）；
  3. **自己没填、由子目标推出来的** —— 整条盖一层斜纹（`rm-hatch`），标题旁一枚箭头，只有推出来的那一头渐隐。推算值不落库：后端给 `derived_start` / `derived_end` 与 `derived{start,end}`，**界面只认这对布尔值，不去猜 `planned_*` 是不是空**；
  4. **完全没有日期** —— 幽灵条，见下。
  条上悬停出气泡：目标名、区间（按粒度措辞，如「2026年 第4季度」「9月7日那周 到 …」）、负责人、进度、里程碑条数、成果指标。
- **条画在哪只看服务端**：目标带 `planned_start_snapped` / `planned_end_snapped`（按粒度吸附好的起止，每一档都吸），画条只用它们；`planned_start` / `planned_end` 仍是原值，拖动时在原值上加减。
- **里程碑 = 条上的菱形**（沿用 `gantt/MilestoneMarks`）：逾期实心红、已达到打勾，悬停出名称与日期。挨得太近的合并成一枚，气泡里列全。**这是路线图上唯一出现具体某一天的地方**——里程碑的日期是承诺，条的起止不是。改法有三种（从「目标 · 甘特图」并过来的，§11）：**拖菱形**改日期（合并成一枚的那种不拖也不点，只给气泡）；**点菱形**出小气泡（确认已达到 / 撤销 / 编辑 / 删除，`roadmap/MilestonePopover`；删除过一道确认）；**在行的空白处双击**就地新建，内联输入名称、回车保存、Esc 取消，日期取双击处并吸到当前刻度**下层**那一格的头上（年档是那个月的 1 号，其余是那一周的周一）。改不动这个目标的人建不了也拖不动，气泡里只剩内容。
- **截止日**：条外的一道 1.5px 短刻度加一个「截止」小标，画在那一天的末尾；已经过了还没达成的画成告警色。它与条说的不是一回事——条说打算什么时候做，这一道说最晚什么时候。（也是从「目标 · 甘特图」并过来的。）
- **「还没排期」**：时间线底部一个常驻分组（不是弹层），左侧照常显示信息列（第二行标出它的上级目标），右侧从今天线起画一根极淡的虚线幽灵条，旁边一句「按住往右拖就算排期了」。工具条上的「只看已排期」把这一组收起。
- **泳道**：默认按团队，可切按负责人 / 按时间桶 / 按类型 / 不分组。分组方式是**一张描述表**（`roadmap/model.ts` 的 `laneSpecs`，每项 `{key, title, of(goal), emptyTitle?, weight?}`），工具条直接照它渲染；再加一档只是往数组里加一项。没有分组值的那一道永远沉到最后。
- **条的颜色**只在一个函数里决定（`roadmap/model.ts` 的 `barTone`）：默认**按状态**（进行中 = accent、已达成 = success、已放弃 = 灰色虚线），可切**按类型**（底色取目标类型自己的颜色，没分类退回中性色）。两种都保持"按进度填充"。
- **交互**：拖条身移动（长短不变）、拖两端改长短，吸附到当前刻度的边界（季度刻度按月吸，其余按周吸）；松手写 `planned_start` / `planned_end` 并把粒度落实成「到周」（`PATCH /goals/{id}`）。幽灵条按住往右拖即写入计划起止。泳道内用行首的把手上下拖动排序（`PUT /goals/rank`，整条泳道的新次序一起发）。条区空白处双击内联新建里程碑。单击行选中、回车进目标详情。没有编辑权的人拖不动，按一下给出整句理由。
- **空状态**：一个目标都没有 →「路线图上还没有目标。先建一个，把它拖到时间线上。」加「新建目标」；筛掉了 →「没有符合这些条件的目标。」加「清空筛选」；有目标但都没排期 → 时间区一句「还没有目标排上时间线」，下面仍是「还没排期」那一组。
- **窄屏（<1024px）**：信息列压到 200px 且只留折叠箭头、信心度圆点与标题，其余进悬停气泡；刻度强制为季度（不摆一个点了也不会变的控件，改成一句说明）。
- **复用**：刻度、两层表头、今天线、缩放锚点、左列固定与拖宽、全屏都来自 `gantt/GanttFrame` + `useGanttScale` + `useGanttShell` + `GanttControls`；菱形来自 `gantt/MilestoneMarks`，气泡来自 `gantt/Floating`。路线图只注入"行是什么"与那四种条的画法。`scales.ts` 只加了两处：`scaleFor` 可以限档，`buildHeader` 的 `minUnit="week"` 让周档的下层画周而不是天——路线图的表头上也不该出现某一天。
- **默认页签与记忆**：地址栏有 `?view=` 就听它（`?view=tree` 的旧链接照旧可用）；否则用这个人上次切过的那一个（`localStorage axiomos.goals.view`），没切过就是路线图。与「任务」页同一套（§10）。**`?view=gantt` 落到路线图**：不听记忆，直接 `replaceState` 改写成 `?view=roadmap`，地址栏不留旧值；记住的选择里存着 `gantt` 的人也解析成路线图。
- **类型筛选写在地址栏**：`?type=<id>`（或 `none` = 还没分类）两个页签都认——路线图在前端按它过滤，树直接把它交给 `GET /goals?type=`。页签下面挂一枚可去掉的芯片「类型：产品 ✕」，去掉即清空；路线图工具条上的类型下拉与它是同一个值，改下拉就改地址栏。组织设置「目标类型」里的「看用了这个类型的目标」跳的就是这个地址。
- **范围**不另设控件：状态栏的范围选择器（ADR 0013）管全站，请求自带 `scope=`。
- **写死的三档**：时间桶只有三档、信心度只有三档、时间粒度只有五档，都不做成可配置词表（ADR 0014 的边界：管理策略可配，表达方式写死）。**目标类型是例外**——它是组织自己维护的词表（ADR 0023）。名字不在前端拼：目标对象带 `horizon_title` / `confidence_title` / `date_precision_title`，类型带自己的 `name` 与 `color`。
- **就地编辑**：目标详情 ② 段多五行——成果指标（单行文本）、时间桶、信心度、**类型**、**时间粒度**（下拉），与其他行同一套控件与失败提示（§15）。

### 26. 接入链接的落地页 `/connect/`（ADR 0024）
同一条地址的两面：Agent / `curl` 取 `GET /connect` 拿到一份**写给 Agent 看的**操作说明（Markdown，后端生成）；浏览器带 `Accept: text/html` 被 303 到 `/connect/` 这张静态页。所以这张页面**只做一件事**：让人把那条链接原样拿走。

- **公开页**：`AppShell` 把 `/connect` 归进 `bare`（和平台后台、邀请页同一档）——不查会话，也就不会被 401 弹去登录页。**没有侧栏、没有舷窗带、没有范围条**。
- **一栏居中，最宽 560px**：舰徽 24px + 「AxiomOS」→ 一句 `text-headline` 的话「把下面这条链接贴给你的 Agent，它会带着你完成接入。」→ 眉标「接入链接」+ **16px 等宽的整条地址**（`code-bg` 底、遥测色、长了折行不截断）与右侧主按钮「复制」（<640px 时按钮落到下一行、占满宽）→「接下来会发生什么」四句大白话（等宽两位序号 01–04：给你验证码 / 你在网页上确认并选授权 / 它把令牌存进自己的配置 / 它连上来自检并告诉你结果）→ 细线之上折叠的**「我想自己动手」**（`curl … | sh` 一行 + 「把 client 换成 cursor、codex 或 custom」+ 去「Agent」页手工注册）→ 底部语言切换。
- **地址从页面自己的来源算**（`api.agentAuth.onboardUrl()` → `publicBase()` → `window.location.origin`）：任何部署下复制到的都是那个部署自己的地址，页面里不写死任何域名。
- **语言**与登录页一样由 `LocaleProvider` 解析（`localStorage` → `navigator.language`），页面底部留一个切换——它可能被没登录过的人打开。**主题**跟随首屏那段偏好脚本，深浅两套都是这一套 token，不像品牌页那样锁深色：这张页不演太空，它只是一张要人复制一行字的纸。
- 内容比视口高时（窄屏展开「我想自己动手」）用 `my-auto` 而不是 `justify-center`，顶部不会被裁掉。

### 27. 我的日程（ADR 0032）
侧栏第二个入口，与「我的工作」同级（`/schedule/`；旧地址 `/?tab=schedule` 自动跳过来），快捷键 `g s`：把占据一个人时间的安排放在一起看——任务的计划起止与截止、目标的计划起止、里程碑到期、外部日历里的会议。**日程不是新对象**（同 §25 的路线图）：这里不能新建、不能拖动，改日期去任务页、路线图或外部日历。

- **三档粒度写死**：日 / 周 / 月，`Segmented` 切换、记本地（`axiomos.schedule.scale`）；周从周一起。前后翻页 + 「今天」。
- **四类各有画法**（`schedule.css`，类名 `sc-*`）：任务 = 按状态类型着色的 20px 条（未开始 neutral、进行中 accent、等待 warning、已完成 success、逾期 danger），标题前带 `#序号`；只有截止日的任务画成一枚**小旗**；目标 = 淡一级的底条（6% accent 底 + 左侧 2px 边，`--c-ink-muted` 字），它是背景不是当天要做的事；里程碑 = 8px 菱形 + 名字（未到空心、已达到 success 实心、逾期 danger 实心，与 §11 一致）；会议 = `surface-3` 底 + 右侧来源小字（飞书 / 企业微信 / Google），带时刻的显示 `HH:mm–HH:mm`。**别人的会议只画成「忙」**：斜纹底、没有标题与链接。
- **跨天的条只画一根**（所有者 2026-09-10 定的）：一条任务或目标覆盖几天，就是横跨这几天的一根条，文字压在条上跨天显示，不是每天一枚重复的小条。排布用泳道（`layoutRow`）：长的先排、同长按目标 → 里程碑 → 任务 → 会议，每根放进第一条放得下的泳道；周视图排在全天带里（`sc-band` 底下按天分格、上面 `sc-lanes` 泳道），月视图按周一行（`sc-mweek`），跨周的条在每周各画一段、跨出去的那端不收圆角也不画边线。月视图一周最多四条泳道，放不下的在那一天格子底部记「+N」，点了进那一天；点日期数字也进那一天。
- **周 / 日**：左侧 56px 时间轴（07:00–21:00，每小时 40px），顶部「全天」带放跨天与无时刻的项（任务、目标、里程碑、全天会议、截止旗），下面按时刻摆会议，今天列淡 accent 底、今天线是 1px accent + 圆点。跨天的条在中间与末尾的格子去圆角、隐去文字，读成连续的一根。
- **月**：7 列、按周成行，每格最多 4 条，多的写 `+n`；非本月的日子 `surface-2` 底。
- **团队**：`我的 / 团队` 切换；团队从**组织树**上任选一个节点（下拉顶上一档是整个组织、写组织自己的名字，下面按层级缩进，来自会话里的范围档位，看不到的团队不列），默认是自己所属的最近那个团队（层级最深的），不属于任何团队就默认整个组织。团队视图是**整个团队的安排合在一张表里**——成员的任务，加上归口到这个团队（含下级）的目标与里程碑，**不带任何人同步来的个人日历**（图例里也没有「会议」）；日 / 周 / 月三档与「我的」同一套画法，每条前面带谁的名字（`sc-who`，名字随日程项带回来，负责人不在名单里也有名字），图例里列出团队人数与名单。不做一人一行：那是花名册，不是日程。**没有安排也照样画格子**：日历本身就是信息（今天在哪、周末在哪），空只在图例下提示一句（`sc-empty`），不放空态插画。
- **图例**一行：四类色样 + 接上的外部日历来源。空态一句「这周还没有安排」。
- 点一条：任务、目标、里程碑跳到各自详情；会议在新标签打开外部日历里的那一条（有链接时）。
- **窄屏（<768px）**：时间轴压到 40px，来源小字与时刻隐去。
- **组织设置 · 外部日历**（`CalendarTab`）：一家提供方一张卡，可同时接几家。卡内：状态一行（已接入 / 已停用 / 未接入 · 已连接几人 · 最近同步与结果）→ 凭据（飞书 / 企业微信沿用 IM 集成的应用凭据，这里只补日历专用字段；Google 登记 OAuth 客户端并给出要填进客户端的回调地址）→ 保存即检查 → 检查项逐条（复用 §14 向导的 `CheckRow`）→ 立即同步 / 停用 / 断开（断开走 `ConsequenceDialog`）。失败原因整句显示在卡顶。
- **个人设置 · 我的外部日历**：飞书 / 企业微信按 IM 身份自动对上，显示「已连接」；Google 一枚「连接 Google 日历」跳去授权，回来带 `?calendar=connected|denied|failed` 提示一句；已连接的可断开。
- **个人设置 · 自助的日历**（同一面板的下两段，`SelfServiceCalendar`，按后端给的字段渲染）：「日历订阅链接」一行输入，「CalDAV 账号」三行（服务器 / 账号 / 密码，企业微信与 iCloud 用它），填好点「连接」就连上，不用管理员。保密字段永远不回显：连上后只显示日历名、最近同步时间与结果、失败原因整句（危险色）；「重新填」展开同一个表单，「断开」直接断。「在哪里找」折叠着列各家日历软件的路径与一句提醒。
- **个人设置 · 把 AxiomOS 订阅到你的日历软件**（`FeedSection`）：没有时一枚「生成订阅链接」；有了显示 `CopyLine` 链接 + `webcal://` 链接、一句「链接就是密钥」的提醒、折叠的「怎么订阅」四条路径；「换一条链接」与「停用」都过 `ConsequenceDialog`，因为旧链接立刻失效。
